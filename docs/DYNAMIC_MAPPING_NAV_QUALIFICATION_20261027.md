# 动态建图、地形概率与导航联调记录（2026-10-27）

这是局部资格检查记录，不是正式批量实验报告，也不是全场景成功率结论。正式批量/对比实验仍未启动。所有失败运行和源码快照保留；本轮没有提交或推送 GitHub。

## 修正内容与接口

1. 新增 `src/dynamic_map_filter`，固定官方 DUFOMap/UFOMap 与 FreeDOM 版本，接入 FAST-LIO 的累计地图维护、IKD 注册树删除及重新入图过滤。默认可选 `none/dufomap/freedom`，当前扫描不被该分类过滤。
2. FreeDOM 采用原仓库的 0.10 m 子体素和 2/5 层级；在本地修正 `MRMap::map_removal` 中第二层 aggressive 关联的反向条件。独立同一扫描线状点列用例在修改前失败、修改后通过，断开的点仍保留。完整上游出处、ROS1 解耦补丁及实质修正分别保存在 `vendor/freedom/` 中。
3. 动态控制增加带停车终端的短程前进候选。通过完整车体、当前占据、移动预测、姿态/路径/停车风险检查后才能执行；否则制动/退让。不允许预测轨迹覆盖当前实测障碍。动作每周期重新验证，目标变化、时钟回退、新占据或过期输入会撤销。
4. 坡道测试暴露 GP 二次趋势外推不适定：单侧可见坡面会把盲区中的起始平地拟合成弯曲地面。将二次曲率与 RBF 残差使用同一已有高斯先验尺度；仿射高度/坡度仍无惩罚。未增加假观测、未增大可通行区域门槛、未放宽物理阈值和风险预算。记录快照的起始足迹从 12/36 格一致恢复到 36/36 格；这只是快照诊断，闭环结果另列。

共享场的线性模型为 `h(x)=φ(x)ᵀw`。精度矩阵为 `ΦᵀΣ⁻¹Φ+Λ`。原先 `Λ` 的前六项均为零（含三个二次项）；现仅前 3 项（常数及两个一次项）为零，其余项为 `1/0.04²`。后验均值与协方差按同一精度矩阵计算，共享协方差传播及 CPU/CUDA 概率核不变。记录输入回归包含真实测得的地面格、注册扫描和估计位姿，不包含仿真地形真值。

链路保持以下角色：

| 数据 | 用途 | 禁止混淆的含义 |
|---|---|---|
| `/cloud_registered` | 原始当前回波 → GPU地形分析与实时碰撞检查 | 不用清残影结果替代当前障碍 |
| `/cloud_registered_visual` | 完整当前回波 → 显示、支撑与头顶净空检查 | 不按注册体素降采样显示，也不补造测量点 |
| `/Laser_map` | 清理后的累计历史图；资格配置中仅作 advisory 记忆 | 不是实时安全地面证据 |
| GP 均值、共享因子与 discrepancy | 构造整体足迹的坡度、侧倾、台阶/残差事件风险 | 不是只对各点方差着色，更不是校准完成的真实故障概率 |
| 初始 `stable_stance` | 用户允许的仿真固定初始足迹假设 | 不随车扩张、不加入训练数据、实车仍关闭 |

车体尺寸与一次安全边距保持前/后/半宽 `0.68/0.58/0.50 m`；接地分析足迹与外包围碰撞轮廓分别处理。状态/局部路径/停车风险预算保持 `0.05/0.10/0.05`，坡度/侧倾/台阶限制保持 `0.55/0.45 rad /0.18 m`。

## 验收口径

* 到达：本轮是**位置到达并停车**，不包括终端航向精度验收。当前跟踪器是 Pure Pursuit/Stanley 混合控制，不是 MPPI。
* 残影：旧障碍 ROI 内、比冻结实测参考地面高 0.30 m 的历史点数，需在 1.5 s 内降至离开前峰值 20% 以下，并持续满足；不是宣称所有旧点归零。
* 实际相遇：额外检验保持触发时速度/航向的反事实轨迹会与移动障碍物重叠，防止将“远处已经穿过”的场景误算避障成功；该真值只用于评价，绝不输入规划。
* 车体净距：使用包围真实车体的有向矩形与圆柱、对齐的真值采样计算。正净距不是连续时间全世界碰撞证明。
* 速率使用新时间戳统计，同时保留源数据年龄。命令间隔及障碍响应用仿真时间，辅助/规划计算耗时用墙钟，二者不混用。

## 检查与限制

最终检查显式开启 `BUILD_TESTING=ON`，不把关闭 CTest 时残留的旧测试二进制视作新代码验证。FAST-LIO 射线/地面参考检查、动态过滤两个测试套件、导航五个套件均已实际执行并通过；其中运动模型 15 项、新增前进绕让与占据撤销检查均已重新编译执行。FSGP/概率/显示 Python 包 310 项通过，曲率模型相关 CPU/GPU 子集 47 项通过。启动/传感器安装/当前扫描发布顺序另有 77 项检查。相关日志均在 `log/`，有修改前失败的关联回归及不达标的物理测试，未覆盖失败。

耗时统计也已修正：仅在动态检查函数正在执行时报告 `dynamic_evaluation_ms`，并发布 `dynamic_evaluation_current` 和 `dynamic_yield_active`。此前其他控制分支可能把“距上次检查的等待时间”记为计算耗时，故旧坡道记录中的该字段不用于计算性能结论。真实命令间隔、源年龄和原始记录仍保留。

`195747` 中有效动态计算日志样本 P95 0.257 ms、最大 0.267 ms。这是该次控制诊断样本的耗时，不是所有场景最坏时延的保证。局部路径预算每次按当前局部轨迹检查，不构成整个任务全程故障概率上界。

这里的动态避障与清理场景使用 GUI 和真实物理车辆，但地图是受控轻量测试课程；相机关闭。不能据此保证高纹理全火星场景、高分辨率相机或所有坡度都满足相同速率。FreeDOM 静态地形理想回归通过；遮挡/噪声条件的广泛静态保留率、长时间重定位与后续正式批量实验仍需要独立验收。

FreeDOM 历史标签是推断，不是实测自由空间。没有把 GMO 的“无效”标志直接当作无限远空射线，也没有用超时全删历史或把未知区域涂成安全。DUFOMap 与 FreeDOM 辅助核是 CPU C++；地形/共享 GP 的 CUDA/CuPy 路径仍在使用。

## 分模块启动

仿真、地形和规划的已验证参数见 [MID360 资格记录](MID360_TILT25_QUALIFICATION_20261027.md)。本轮将其建图命令改为：

```bash
scripts/sim/start_mapping.sh rviz:=false dynamic_filter_backend:=freedom
```

完整四终端顺序（相机默认关闭；仿真固定足迹假设须显式启用）：

```bash
# 终端1：仿真与传感器
scripts/sim/start_simulation.sh --lidar-quality mid360_csv

# 终端2：建图与历史动态点辅助处理
scripts/sim/start_mapping.sh rviz:=false dynamic_filter_backend:=freedom

# 终端3：GPU地形、共享GP风险与统一RViz
scripts/sim/start_terrain_analysis.sh terrain_backend:=gpu fsgp_gpu_backend:=cupy \
  prediction_backend:=feature_sgp gp_device:=cuda probability_model:=shared_gp \
  gp_complete_supported:=true probability_gp_max_distance_m:=1.25 \
  probability_gp_max_extrapolation_m:=0.75 startup_support_mode:=stable_stance \
  startup_support_directional:=true obstacle_memory_topic:=/Laser_map obstacle_memory_role:=advisory

# 终端4：规划与跟踪
scripts/sim/start_planning_control.sh chance_allow_gp_completion:=true \
  chance_allow_joint_model:=true chance_allow_startup_prior:=true reverse_recovery_enable:=true
```

自动导航期间不同时运行键盘命令发布器；在统一RViz中使用目标点工具发目标。以上命令保留默认 Mars 场景，表中闭环资格采用脚本明确指定的轻量受控课程，两者的渲染负担不应混同。

辅助模块源码、参数、原始版本与本地补丁见 [模块说明](../src/dynamic_map_filter/README.md)。默认是否启用应以最终资格结果为准，勿把 `none` 和 `freedom` 的记录混成同一版本。
