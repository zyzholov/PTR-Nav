## 详细说明

### 1. Gazebo 仿真环境层

**传感器配置:**
- **Hunter SE 车辆底盘**: Ackermann 转向模型，轮距 0.55m，接收 `/hunter_se/cmd_vel` 话题（速度 + 转向角）
- **Livox MID360 激光雷达**: 非重复扫描式激光雷达，发布 `/livox/lidar` 话题（点云）
- **IMU 惯性测量单元**: 外置 IMU 模块；Isaac 主话题为 `/imu/data_raw`，旧 Gazebo/配置兼容 `/livox/imu`

**数据流:**
- 车辆底盘通过 `cmd_vel` 接收控制指令
- 激光雷达和 IMU 数据同步发送给 FAST_LIO2 进行位姿估计

---

### 2. FAST_LIO2 层 (激光雷达惯性里程计)

**核心算法:**
- **点云预处理**: 去除无效点、降采样
- **iEKF (迭代扩展卡尔曼滤波)**: 融合激光雷达和 IMU 数据，估计 6DoF 位姿
- **ikd-Tree (增量 KD 树)**: 高效的点云地图数据结构，支持增量更新
- **点云配准**: 将当前帧点云配准到世界坐标系

**输出话题:**
| 话题 | 频率 | 数据格式 | 说明 |
|------|------|----------|------|
| `/Odometry` | ~200Hz | `nav_msgs/Odometry` | 6DoF 位姿估计 (位置 + 四元数) |
| `/cloud_registered` | ~10Hz | `sensor_msgs/PointCloud2` | 配准后的单帧点云（世界坐标系） |
| `/cloud_local_map` | ~10Hz | `sensor_msgs/PointCloud2` | 局部累积点云地图 |

---

### 3. Terrain Analyzer 层 (地形分析器)

#### 3.1 Ego Body Filter (本体过滤器)

**作用**: 去除激光雷达扫描到车辆自身的点，避免自检测干扰地形分析。

**参数配置** (`hunter_fastlio_registered_live.yaml`):
```yaml
ego_body_filter_enable: true
ego_body_filter_front_m: 0.50    # 车辆前方过滤距离
ego_body_filter_back_m: 0.50     # 车辆后方过滤距离
ego_body_filter_half_width_m: 0.30  # 车辆半宽过滤距离
ego_body_filter_z_min_m: -0.55   # 垂直方向下限
ego_body_filter_z_max_m: 1.40    # 垂直方向上限
```

**过滤区域**: 以车辆中心为原点，前后各 0.5m，左右各 0.3m 的矩形区域内的点被丢弃。

#### 3.2 第一遍扫描: 地表更新

**处理流程:**
1. 每个激光点经过 Ego Body Filter 过滤
2. 世界坐标转换为栅格索引 `(gx, gy)`
3. 更新三个地图层:
   - **elevation_map_**: 指数移动平均，低点权重 0.85，高点权重 0.05（低点优先，适应地面）
   - **top_elevation_**: 取最大值，记录该栅格的最高观测点
   - **point_count_map_**: 观测点数计数器

**设计原理:**
- 低点优先更新是为了让高程图代表"地面"而非"障碍物顶部"
- 使用指数移动平均而非简单平均，是因为需要平滑噪声同时保持响应性

#### 3.3 第二遍扫描: 障碍物检测

**处理流程:**
1. 对每个激光点调用 `estimateObstacleReferenceGround()` 估计该点附近的地面高度
2. 计算点相对于地面的高度: `rel_h = pt.z - ground_z`
3. 调用 `isCollisionBandPoint()` 判断是否为障碍物点:
   - **高度条件**: `obstacle_min_height (0.28m) < rel_h < obstacle_max_height (1.45m)`
   - **垂直结构条件**: 同一栅格内高度跨度 > 阈值（检测垂直面如树干）
4. 调用 `recordCollisionEvidence()` 记录障碍物证据:
   - `obstacle_band_count_map_[idx] += hit_increment (4)` — 累积障碍物命中次数
   - `collision_top_elevation_map_[idx] = max(当前, pt.z)` — 记录障碍物顶部高度
   - 当累积次数足够时，`vertical_obstacle_map_[idx] = 1` — 标记为垂直障碍物

**生命周期管理:**
- 每次更新时，未命中的栅格衰减: `obstacle_band_count_map_ *= decay (0.98)`
- 当计数低于阈值时，清除障碍物标记: `obstacle_persistence_misses = 18`

**关键阈值:**
| 参数 | 值 | 说明 |
|------|-----|------|
| `obstacle_min_height` | 0.28m | 低于此高度视为地面 |
| `obstacle_max_height` | 1.45m | 高于此高度视为噪声或头顶物体 |
| `obstacle_seed_max_height` | 0.50m | 障碍物种子最大高度 |
| `obstacle_min_points` | 2 | 最少观测点数才标记为障碍物 |
| `obstacle_hit_increment` | 4 | 每次命中增加的计数 |
| `obstacle_count_decay` | 0.98 | 每次更新的衰减系数 |
| `obstacle_persistence_misses` | 18 | 连续未命中次数后清除 |

#### 3.4 publishTerrain: 地形发布 (15Hz 定时器)

##### 3.4.1 computeTraversabilityMetrics() — 可通行性评估

**处理流程:**
1. **中心差分法计算地形特征:**
   - **坡度 (slope)**: 相邻栅格高程差的最大梯度
   - **曲率 (curvature)**: 高程的二阶导数，反映地形凹凸程度
   - **台阶高度 (step_height)**: 相邻栅格高程差的最大绝对值

2. **软阈值映射 (Soft Threshold + Gamma):**
   ```
   score = 1 / (1 + exp(-gamma * (value - threshold)))
   ```
   将原始特征值映射到 [0, 1] 范围内的分数。

3. **加权合成风险值:**
   ```
   risk = (w_slope × score_slope + w_curvature × score_curvature + w_step × score_step)
          / (w_slope + w_curvature + w_step)
   ```

**风险评估阈值:**
| 特征 | 自由阈值 | 硬障碍阈值 | 权重 | 说明 |
|------|----------|------------|------|------|
| 坡度 (slope) | 0.55 rad | 1.10 rad | 0.22 | ~31° 以下视为可通行 |
| 曲率 (curvature) | 0.45 | 1.00 | 0.33 | 地形凹凸程度 |
| 台阶高度 (step_height) | 0.09m | 0.22m | 0.45 | 相邻栅格高程差 |

**风险权重分析:**
- 台阶高度权重最高 (0.45)，因为台阶对车辆影响最大
- 曲率权重次之 (0.33)，反映地形平滑度
- 坡度权重最低 (0.22)，因为车辆有一定爬坡能力

**风险图解释:**
- `risk = 0`: 完全可通行（平坦、无台阶）
- `risk = 0.5`: 中等风险（轻微坡度或台阶）
- `risk = 1.0`: 高风险/不可通行（陡坡、大台阶）

##### 3.4.2 障碍物标记与膨胀

**处理流程:**
1. **合并障碍物来源:**
   - `vertical_obstacle_map_`: 激光雷达检测到的垂直障碍物
   - `terrain_hard_obstacle`: 风险图中的硬障碍物（可选）

2. **生成二值障碍物图:**
   - `obstacle_map[idx] = 1` (障碍物)
   - `obstacle_map[idx] = 0` (可通行)

3. **障碍物膨胀:**
   - 膨胀半径: `vertical_obstacle_inflation_m = 0.41m`
   - 膨胀栅格数: `inflate_cells = ceil(0.41 / 0.20) = 3 格`
   - 以每个障碍物栅格为中心，半径 3 格的圆形区域标记为障碍物

4. **Ego Clear (车辆本体清除):**
   - 清除车辆本体范围内的障碍物标记
   - 保留近距离 (`0.12m`) 的真实障碍物证据

**膨胀的目的:**
- 为车辆提供安全裕度
- 避免规划器生成过于贴近障碍物的路径
- 膨胀半径 0.41m 略小于车辆半宽 (~0.3m)，确保车辆可通过的间隙不会被完全堵死

##### 3.4.3 Chamfer 距离传播 → SDF Map

**算法原理:**
SDF (Signed Distance Field) 通过两遍扫描计算每个栅格到最近障碍物的距离。

**前向传播 (左上→右下):**
```
dist[i][j] = min(dist[i][j],
                 dist[i-1][j] + 1,
                 dist[i][j-1] + 1,
                 dist[i-1][j-1] + √2,
                 dist[i+1][j-1] + √2)
```

**后向传播 (右下→左上):**
```
dist[i][j] = min(dist[i][j],
                 dist[i+1][j] + 1,
                 dist[i][j+1] + 1,
                 dist[i+1][j+1] + √2,
                 dist[i-1][j+1] + √2)
```

**距离转换:**
```
sdf_distance = dist × resolution (0.2m/格)
```

**SDF 图解释:**
- `sdf_distance = 0`: 障碍物表面
- `sdf_distance = 0.5m`: 距离障碍物 0.5m
- `sdf_distance > 2.0m`: 远离障碍物，安全区域

**设计原理:**
- Chamfer 距离是欧氏距离的良好近似，计算效率高 (O(n) 复杂度)
- 两遍扫描确保距离传播的正确性
- 使用对角线距离 (√2) 提高精度

### 4. Plan Manage + Path Search 层 (规划器)

#### 4.1 Kino A* 前端搜索

**碰撞检测:**
```cpp
bool isCollided(state) {
    sdf_distance = sdf_cpu.query(state.x, state.y);
    return (sdf_distance <= safe_dis);  // safe_dis = 0.42m
}
```

**代价函数:**
| 代价项 | 权重 | 说明 |
|--------|------|------|
| 前进距离 | 1.0 | 前进的基础代价 |
| 后退距离 | 2.0 | 后退代价更高，鼓励前进 |
| 换挡 | 14.0 | 换挡代价很高，避免频繁换挡 |
| 转向角 | 0.75 | 转向角越大，代价越高 |
| 转向角变化 | 0.85 | 转向角变化越大，代价越高 |

**设计原理:**
- 后退代价是前进的 2 倍，鼓励规划器优先选择前进路径
- 换挡代价很高 (14.0)，因为换挡需要停车，影响效率
- 转向角代价鼓励平滑路径

#### 4.2 轨迹优化后端 (ALM + L-BFGS)

**ESDF 代价:**
```cpp
for (each footprint corner on trajectory) {
    sdf_distance = sdf_query(corner.x, corner.y);
    cost += esdfWei × max(0, safe_margin - sdf_distance)²;
}
```
- `esdfWei = 1.05`: ESDF 代价权重
- `safe_margin = 0.42m`: 安全裕度
- 使用车辆 footprint 的 4 个角点进行碰撞检测

**风险代价:**
```cpp
risk = risk_map.query(x, y);
cost += risk_weight × max(0, risk - risk_threshold);
```
- 风险阈值以上的区域才会产生代价
- 鼓励规划器选择低风险路径

### 6. 三种地图的作用总结

| 地图 | 消费者 | 作用 |
|------|--------|------|
| **高程图** | Risk 计算、障碍物检测 | 提供每个栅格的地面高度，是所有地形分析的基础 |
| **Risk 图** | 轨迹优化器 | 评估地形可通行性：坡度、曲率、台阶高度的综合风险 |
| **SDF 图** | A* 碰撞检测、轨迹优化器 | 提供到障碍物的精确距离，用于碰撞判定和避障梯度 |

### 为什么需要这三种地图？

1. **高程图**是最原始的数据——激光雷达点云的地面高度摘要。它本身不能直接告诉规划器"能不能走"。

2. **Risk 图**回答了"地面是否平坦"的问题。一辆车即使前方没有障碍物，如果地面太陡或有大台阶，也是不可通行的。Risk 把高程信息转化为一个 [0,1] 的可通行性指标。

3. **SDF 图**回答了"离障碍物多远"的问题。它把二值的障碍物标记转化为连续的距离场，让规划器不仅能判断"碰不碰"，还能判断"离多远"，从而规划出安全裕度更大的路径。

三者互补：**SDF 处理"硬障碍"（树干、墙壁），Risk 处理"软障碍"（陡坡、台阶），高程图是两者的共同基础。**
