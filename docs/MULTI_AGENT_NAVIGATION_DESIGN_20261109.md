## 3. 需要完成的接口和算法层次

```text
实际传感器/FAST-LIO
 ├─地形观测 → FSGP/SEB → 带源时间与版本的地形风险查询
 └─当前实测障碍 → 多物体关联/状态估计 → 带时间的多假设预测
                                    ↓
任务路线 → 多种可通行方式的候选 → 受地形/车身/动态约束的滚动轨迹优化
                                    ↓
                     当前输入重验 → 控制执行/可执行备选动作
```

1. **感知和预测。** 每个物体独立保存身份、实测形状、最后观测时间、速度及质量状态。分清有效、歧义、暂失和确定静止；不能把缺测当静止。预测至少显式区分继续运动、减速停车及观测支持的转向。没有校准数据时，误差界是工程假设，不能宣称是已校准行人事故概率。实例归属不清的原始碰撞格继续保留。
2. **行为与空间选择。** 至少同时评估左绕、右绕、让行后通过和有支撑的后退再进入；从当前真实速度和转角出发，而非只对某个停止位置发零速度。候选需要考虑全部相关物体，并保留前一周期可行选择，避免反复换边。候选数量、计算时间、被否决原因可观测。
3. **运动优化。** 使用 NEOS 0.430 m 轴距、底盘中心与后轴的 0.215 m 偏置、实车转角上限和实际加减速/转角变化限制。优化变量应包含速度与转角随时间的序列；倒车先经过零速，不能把角速度直接当转角。不能将现有 random-shooting MPC 称作已实现的 MPPI。
4. **约束与备选。** 地形的姿态、路径及制动预算继续分别检查；动态占用按对应未来时刻检查整车，不能用所有未来位置的空间并集替代时序碰撞。停车位置也会被撞时，零速度命令不等于安全备选。执行前绑定当前输入版本，旧轨迹只作候选，不作运动许可。
5. **调度。** 优先确定高频碰撞/状态处理与控制提交，限制后台候选搜索、地形后验和显示对执行的阻塞。GPU 是否参与优化取决于包括 RTX 和地形任务在内的实测负载；先保留有界 CPU 路径，不能因为使用 GPU 就声称低延迟。

## 4. 风险语义不能混淆

地形风险来自高程及相关性模型，动态碰撞风险来自其他物体的运动预测；二者不是同一随机变量。沿轨迹每个时刻必须同时满足地形支撑/车型约束和动态几何约束。若以后采用动态机会约束，必须单独建立并校准运动误差模型和风险预算，不能把现有地形概率复制给行人。

仿真固定初始支撑与独立 5 mm 模型底噪仍是显式、未实车校准的假设；没有扩大初始区域，也不将后方未知地面自动变安全。实车维持原禁用策略。

## 5. 后续定向资格序列

先完成模块反例及小规模集成，保留每个版本原始失败。每阶段不超过事先限定的冷启动次数；大规模方案待审阅。

| 阶段 | 对象 | 要区分的失败 |
|---|---|---|
| 数学与原生回归 | 两侧同时横穿、后方来物、迎面后停车、未知后方、身份歧义、丢帧 | 每个候选是否对所有物体成立，是否存在不允许的换向或旧证书 |
| 执行时序回放 | 本次有窗口真实输入及控制记录 | 已确认运动到候选、候选到执行、恢复等待、地图交付间隙；避免只统计快速等待的耗时 |
| 单物体物理资格 | 与失败相同的窗口/渲染负载 | 实际连续避让、无接触净距、唯一最终目标、到达停稳、接受证书有限有效 |
| 两物体定向资格 | 相向横穿、前方横穿与后方靠近 | 一侧退让不能撞另一物体，停车不能被横穿者扫中 |
| 多物体资格 | 狭窄通道入口、多个交叉方向、密集静态物体混合 | 多种绕行选择、有限回退、死锁恢复、完整链路实时性 |

记录到达与失败原因、最小车身净距、碰撞/接触证据、实际运动与指令、倒车/换边次数、规划/控制耗时分布、源龄和更新间隙。预测误差、身份切换数及不可用时段单列；规划器失败与感知漏检分开。场景真值仅供独立评估，禁止进入控制与预测输入。

目前尚未完成多动态新后端，不用单物体的两次成功替代上述资格，也不把不可观测或物理不可避的初态纳入“必须成功”分母。
