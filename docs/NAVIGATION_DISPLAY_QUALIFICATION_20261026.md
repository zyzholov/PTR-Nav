# 显示、地图更新与导航选路修订记录

日期：2026-10-26。本文是定向工程资格记录，不是论文批量实验或实车安全认证。接续[上一轮资格记录](NAVIGATION_RUNTIME_QUALIFICATION_20261026.md)，不覆盖或删除原先失败。

## 1. 本轮实际修改

### 1.1 控制不再等长搜索释放地图锁

旧版本搜索持有地图锁时，地图回调也会等待，可能造成控制端使用旧图停车。现在先在独立快照中解码、验证、构建代价场，立即更新只读控制快照；后台搜索在下一次搜索开始时采用最新待处理快照。搜索仍基于一个固定版本，控制每次按最新版本复核。无效坐标系或契约失配会立即使控制快照失效，不能继续使用旧图。

新增原生回归实际持有搜索锁，从另一线程送入地图，检查控制图仍能更新、搜索图保持固定、稍后正确采用新图；错误坐标系也不得被锁阻塞。诊断增加 `map_ingress_ms` 与 `deferred_search_maps`。这解决的是锁争用，不等于整个搜索都能在 90 毫秒内结束。

### 1.2 将显示密度与导航密度分开

| 数据 | 用途 | 本轮行为 |
|---|---|---|
| `/cloud_registered` | 当前导航、地形与实时障碍输入 | 保持原有降采样和低延迟优先发布 |
| `/cloud_registered_visual` | 全分辨率当前扫描，只供显示 | 使用同一次校正位姿与真实扫描；有订阅才变换/发布，深度 1 |
| `/Laser_map` | 有界累计地图 | 保持全扫描来源、0.10 米体素、80 万点上限、1 Hz 更新 |
| `/terrain_display/lidar_map` | 累计点云着色 | 高度分层蓝灰色；不删除、增加或移动点 |
| `/terrain_display/lidar_returns` | 当前回波着色 | 距车近为金色，约 8 米为薄荷色，30 米及外为蓝色 |

着色保留 XYZ、点数、坐标系和源时间戳；不是反射率，也没有画虚构激光束或复制点来制造稠密感。显示节点在没有实时显示订阅时释放全扫描订阅。全扫描发布安排在导航扫描和地图维护之后，未修改 EKF、降采样、外参或动态清理参数。两份 Hunter YAML 本轮均未修改。

实际三柱场景同时间戳为导航 4599 / 显示 29937 点；默认 Mars 为导航 7863 / 显示 38158 点。累计地图在三柱任务中由约 3 万增长到约 15 万点，确实不是仅显示当前扫描。扫描自身的离散束线、遮挡和近场盲区仍然存在，不能通过显示设置伪造观测。

### 1.3 风险与高程融合显示，不修改导航概率

- 风险曲面优先采用实测高程；缺测格仅在 `probability_gp_used` 合格时采用 `probability_elevation`。背景 GP 候选不自动成为导航地面。
- 风险颜色改为每个顶点自己的概率颜色，再由渲染插值；取消用一个三角形的最大风险涂满整个面的显示方法，避免视觉上把红色范围扩大。
- 原生网格仍为 0.20 米；相邻有效高程建立三角面，跨度超过 0.25 米不跨接，未知不补成假平面。风险面相对高程抬高 0.02 米避免深度冲突。
- 低风险蓝绿、临近状态门限金色、高风险珊瑚红、未知灰色；图例固定为 0 / 0.1 / 1 / 5 / 100%，不是每帧自动归一化。
- 金色方格轮廓表示当前原始占据格，不代表车身中心的禁行范围。姿态风险考虑整个足迹，红区比柱子本体大有其几何原因；本轮没有缩小车宽、净距或降低风险门限来换视觉效果。
- 风险视图实时回波为低透明度 1 像素；点云视图强调完整扫描与累计地图。高程视图独立显示实测曲面、预测候选和导航合格预测，起始假设仍单独标成琥珀色。

自动探针逐点检查着色输出与原点云一致、风险顶点来自实测或合格预测、没有跨循环缓冲区连接、没有跨大高差填面。默认 Mars 样本实际含 115 个导航合格 GP 曲面顶点，风险面高度跨度约 1.25 米，不是零高度二维贴图。

## 2. 导航失败与处理

113351 三柱任务未到达，不能归为通过。车辆在背景标牌附近停止，估计姿态概率很低，但当前原始占据方格与带余量的车身包络重叠。对应高处回波缺少足够的包围地面证据，净空切片不能证明可以忽略它；冻结现场回放仍应拒绝该路径。

没有直接删除这类高点、借用场景真值，或把未知地面当安全。试用已有的 `obstacle_memory_role:=advisory`，让累计障碍仅影响早期选路，提前远离部分遮挡、仅靠当前扫描不易保持净距的区域。历史数据不进入支撑、碰撞概率或硬障碍层；当前扫描仍即时否决不安全路径。此选项与把历史残影永久投影成硬障碍不同。

该选路策略两次三柱任务均到达，另做了下坡动态检查。它仍是显式仿真选项，默认历史输入保持 `none`；不能凭这几次检查将硬历史、任意净空场景或实车全部视为通过。

## 4. 回归与发布核对

选定的地形、概率契约、启动/运动守护、显示、几何和记录工具完成 **485 项 Python 检查**；原生导航 117 项、转换/曲面 11 项，共 **128 项 gtest，7 个 CTest 目标**通过。没有计入目录里早期遗留的 `test_ground_support` XML，也没有声称检查了所有历史论文数据下载工具。

回归保留了两类失败过程：默认 ROS `launch_testing` 自动收集插件引入了无关历史数据下载测试，因 `remotezip` 缺失而收集失败；限定本次文件并关闭自动插件后，又两次发现 DDS 订阅释放检查在复用测试进程中超时，单独运行通过。后者最终改为独立测试进程、上下文、执行器和唯一话题，仍要求点数/XYZ/时间戳含 NaN 原样保留、错误坐标系不得替代显示、关闭显示后三秒内释放全扫描订阅；未放宽断言，也没有据此声称修复了未知的 DDS 内部根因。

最终选定 Python 回归完整运行两遍，各 485 项通过，不是 970 个独立用例。日志为 `log/navigation_display_pytest_20261026_process.log` 与 `log/navigation_display_pytest_20261026_repeat.log`，原生为 `log/navigation_display_ctest_20261026_final.log`。可用下列命令复跑选定回归，不会启动 Isaac 或批量导航：

`BUILD_TESTING=OFF` 的五包发布构建已完成；26 个实际加载 Python/launch/配置/RViz 文件与源码一致，规划与建图安装二进制逐字节匹配构建输出。发布后的全部记录方法文件与最后一次物理运行相比，仅只读显示测试夹具发生了上述隔离修改，运行算法/配置/二进制没有变化。详见[发布与证据校验](../results/navigation_display_20261026/validation.json)。

## 5. 使用与未达标项

正常启动仍为仿真、建图、地形、规划四个独立脚本，见[脚本说明](../scripts/README.md)。当前限定仿真配置需显式选择共享模型、0.75 米有支撑补全与固定起始支撑假设，软选路需额外指定：

```bash
scripts/sim/start_terrain_analysis.sh terrain_backend:=gpu fsgp_gpu_backend:=cupy \
  prediction_backend:=feature_sgp gp_device:=cuda probability_model:=shared_gp \
  gp_complete_supported:=true probability_gp_max_distance_m:=0.75 \
  startup_support_mode:=stable_stance \
  obstacle_memory_topic:=/Laser_map obstacle_memory_role:=advisory

scripts/sim/start_planning_control.sh chance_allow_gp_completion:=true \
  chance_allow_joint_model:=true chance_allow_startup_prior:=true reverse_recovery_enable:=true
```

两条命令在不同终端运行，须先启动仿真与建图。只保留一个共享导航 RViz。起始假设不会随车移动，实车不可直接照搬。控制器仍为混合 Pure Pursuit / Stanley，不是 MPPI；概率仍是当前共享 GP 模型下的条件上界，未做实车经验校准。

仍需解决：动态净距余量偏小、复杂搜索长尾、缺乏地面净空依据时的保守投影与恢复、持续时效抖动，以及高横梁通过/低横梁拒行的成对物理检查。当前雷达是 Ouster 扫描替代模型，不是 MID360 实测复现。没有启动未经审阅的批量实验，没有提交或推送 GitHub。
