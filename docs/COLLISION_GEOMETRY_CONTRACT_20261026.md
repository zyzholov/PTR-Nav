# 车辆碰撞包络与高度投影修正

日期：2026-10-26。本文是基础逻辑与初次回归记录，不是导航成功验收报告。之后开展的物理试跑、失败驱动修正和同版复测另见[导航实时性与动态避障资格记录](NAVIGATION_RUNTIME_QUALIFICATION_20261026.md)；不能将此处的基础回归数量当作导航次数。

## 1. 发现的问题

此前并非没有读取车辆宽度，而是几类几何量的职责没有统一：

- 完整车身检查之外，仿真配置还设了 0.35 米额外障碍膨胀及 0.36 米硬栅格净距门限。
- 实时障碍分支已经通过 `max(0, footprint_margin - inflation_radius)` 抵扣过一部分余量，因此不能把所有参数简单相加；但较大的额外保留区和硬净距门限仍会让实际没有碰撞的姿态无法通过。
- 旧模式部分检查仅检查 25 个足迹点，点与点之间可能漏掉细柱。
- 垂直柱占据未按完整车辆及载荷的净空一致裁切。地形节点、GP 原始回波否决和原生规划器可能对同一个高处回波作出不同判断。
- 历史真值验收曾将高处标牌面板完整压到 XY 平面，忽略车辆能否从其下方通过。这与算法本身的投影错误是两个独立问题。

因此先停止追加整场景导航试跑，改为几何回归与冻结输入诊断。不能以一批失败试跑代替基础几何检查。

## 2. 车体尺寸、安全余量与栅格

当前参数来自 `src/planner/terrain_nav/config/hunter_gazebo.yaml`，单位均为米。

| 对象 | 前伸 | 后伸 | 半宽 | 用途 |
|---|---:|---:|---:|---|
| 地面支撑模型 | 0.42 | 0.42 | 0.313 | 判断坡度、台阶及轮下地面支撑 |
| 仿真车体碰撞包络 | 0.58 | 0.48 | 0.40 | 包含保险杠、侧护栏及转向轮的保守平面包络 |
| 每侧安全余量 | 0.10 | 0.10 | 0.10 | 只加一次 |
| 最终保护包络 | 0.68 | 0.58 | 0.50 | 总长 1.26，总宽 1.00 |

这些是本工程仿真配置的包络，不是声称 Hunter 出厂尺寸恰为此值。回归检查同时核对场景脚本中所有附加保险杠、侧护栏和角部碰撞盒是否被包络覆盖；轮胎转向和载荷变化仍需独立核实。

车身局部保护矩形为：

`[-max(support_back, body_back)-margin, max(support_front, body_front)+margin]`

`× [-max(support_half_width, body_half_width)-margin, max(support_half_width, body_half_width)+margin]`。

该矩形随车辆航向旋转，再用分离轴判据与**整个占据栅格方形**相交检查。不是只查车辆中心，也不是仅查栅格中心或几个足迹采样点。旧/新规划模式的车身碰撞与实时路径障碍检查统一使用该几何。

仿真配置现为：

```yaml
footprint_margin: 0.10
live_obstacle_inflation_radius: 0.0
hard_clearance_floor: 0.0
```

后两个零值不等于没有安全距离，而是不给已经包含车体及 0.10 米余量的检查再叠默认硬保留区。`clearance_distance: 0.65` 和 `comfort_clearance_distance: 1.35` 仍用于软代价、路线偏好及限速。动态障碍物的运动预测及延迟保留不属于静态车宽膨胀，仍然保留。

0.20 米栅格以整个方形表示占据，仍有离散化保守性：不能据此承诺恰好 1.00 米宽的任意方向通道一定放行。车宽、显式余量、栅格表示误差、动态不确定性必须分开说明。

## 3. 高度投影的输入与判断

### 3.1 不能使用固定世界高度或雷达原点

车辆在坡面上，地面和传感器的世界 Z 会变化。当前采用相对局部支持面的完整车辆高度，而不是“世界 Z 小于某数”或“比雷达低的才是障碍”。仿真配置为：

- `vehicle_envelope_height_m = 0.65`：包括底盘、悬架高度余量和传感器载荷。
- `overhead_clearance_margin_m = 0.10`：额外垂直净空。

0.65 米不是雷达自身高度，也不是 `base_link` 上方 0.65 米。它是车辆相对支持面的整体高度包络。实车安装或载荷改变后必须重新核实。

### 3.2 实测平面门控

`overhead_clearance.measured_ceiling()` 只允许原始实测地形及当前扫描共同提供依据：

1. 原始实测有效、方差有限且不超过 `(0.02 m)^2`。
2. 当前扫描在对应栅格有与实测高程相差不超过 0.05 米的地面回波。
3. 在 0.90 米邻域拟合 `z = a + gx*u + gy*v`，至少 8 个回波支持的栅格，四个开象限均有支持，线性系统非退化。
4. 最大残差不超过 0.04 米，梯度模长不超过 1；已有实测中心与拟合面不一致时不启用裁切。

若中心缺测但被测量包围，平面可提供**碰撞切片的高度参考**，但绝不向地面支撑、GP 训练集或已观测掩码添加一格“安全地面”。单侧未知区域不外推这个参考。

### 3.3 上界与保留规则

令 `e` 为邻域实测最大拟合残差，`H` 为整体车高，`m_z` 为垂直余量。上界为：

`z_ceiling = max(a + e, z_observed_center) + H*sqrt(1+gx^2+gy^2) + m_z`。

没有实测中心时不使用 `z_observed_center` 项。斜面中的根号项对应法向高度在同一 XY 处的垂直分离；原始中心测量不能被平面拟合向下压低。只有 `point.z > z_ceiling` 的回波才从导航副本移除，等于上界时保留。

不符合门控时上界为正无穷，继续原有保守检查，不因缺少依据把区域清空。低横梁、柱子的低处回波和凹坑负证据仍保留。

### 3.4 各模块必须使用同一导航副本

```text
原始 /cloud_registered 与累计 /Laser_map：保持不变
                     |
原始地面测量 + 当前回波 -> 局部实测平面与切片上界
                     |
             导航用高度裁切副本
               /             \
       GP 原始证据否决       FSGP 垂直占据
                                 |
                  collision_risk + ceiling + 尺寸契约
                                 |
                   原生实时占据 + 完整车身碰撞
```

地图新增 `collision_height_contract`、`collision_height_filter_enabled`、`collision_vehicle_height_m`、`collision_headroom_margin_m`。启用裁切的地图若缺少契约、元数据不一致、车高/余量比规划器要求小，规划器会废弃旧可用快照并阻止导航，不能悄悄沿用已裁切的占据图。

原生实时点云仅在地图净空依据不超过 0.30 秒、点云与地图时间差在 `[-0.05, 0.30]` 秒内时使用上界。更旧或来自未来的依据不能移除当前回波。

通用/实车 launch 默认不启用高度裁切；`scripts/sim/start_terrain_analysis.sh` 为本仿真显式启用，支持 `overhead_filter_enabled:=false` 覆盖。

## 4. 日志、图示与验收不混淆

- 启动日志打印最终前/后包络、保护总宽、单次余量、额外膨胀、硬栅格保留及车高/净空。
- `/terrain_nav/chance_status` 新增对应几何字段及 `collision_height_slice_mode`，可核实实际运行参数。
- `body_grid_clearance_m` 明确表示栅格距离变换量。旧 `body_clearance_m` 仅为兼容记录器保留，二者都不能当作独立物理网格净距。
- 对高处标牌的独立验收使用真实位置、俯仰/横滚及完整车辆 `base_link` 垂向范围 `[-0.30,+0.35]` 米；同时保留旧二维投影反事实。该值是采样分离下界，不是连续三维网格碰撞证明。

## 6. 尚不能宣称完成的部分

本基础回归阶段没有追加物理导航试跑；后续试跑已单独记录于上述导航资格文档。上轮三柱等失败记录仍为失败，不能因重绘或参数更正改成通过。此处回归不是 479 次导航，也不证明通用成功率。

这仍是受实测支持约束的 2.5D 点云净空模型，不是三维可见自由空间证明。遮挡下未采样物体、较大悬架姿态偏差、多层地面、完整动态物体垂向体积等仍需额外验证。GP 补全也不是观测到自由空间，更不是经实车校准的安全保证。

下一步须在相同构建与参数下分别验证高横梁可通过、低横梁拒行、支柱避让、上下坡及动态横穿，再恢复较复杂的完整导航资格。不能先扩大批量试跑，再用调参掩盖这些几何边界。
