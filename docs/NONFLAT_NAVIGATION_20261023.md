# 非平坦闭环导航资格测试（2026-10-23）

## 验收对象

本轮检查真实 Isaac 轮地接触动力学下的完整链路：

`LiDAR / 外置 IMU -> FAST-LIO2 -> GPU 地形分析 -> 共享 GP / SEB -> 滚动规划 -> 跟踪控制 -> 车辆`

目标是完成可通过地形上的实际导航，不是只发布路径，也不把未知地面改成安全来提高到达数量。
固定足迹的初始稳定支撑假设和共享 GP 条件模型仍仅限显式授权的仿真，不能当作实车已校准安全保证。
控制器仍是混合 Pure Pursuit / Stanley，不是 MPPI。动态障碍短时运动预测与地形概率约束是两种不同的安全检查。

## 本轮修正

1. 原地形概率模式下，圆弧和 Dubins 的解析车身朝向会被点间连线方向覆盖。现在保留实际曲线朝向，Frenet 使用解析导数，并检查起终朝向、曲率、车身足迹和完整概率预算。
2. 目标在侧前方时，不再用反复短直行抢占已可认证的转弯路线。远处缺测而没有已知危险时，允许朝向对齐的短距离观测推进；整条局部目标射线中的已知危险会阻止该提前推进。缺测不是已测障碍，也不是安全地面。
3. 绕行选择增加对上一条路径的软连续偏好。新障碍仍可以强制换侧；偏好不能覆盖碰撞或地形限制。
4. 提交的路径保留连接段，完整路径重新做联合风险检查。提交功能在当前仿真参数中关闭，但对应代码和回归仍需正确。
5. 所有观测推进、认证的前向短段和不完整格点路径统一标记为谨慎推进，限速 `0.35 m/s`，避免只给其中一种路径限速后被其他不完整路径绕过。固定起始假设仍可进一步限速到 `0.25 m/s`；完整认证路径保留 `1.20 m/s` 期望速度和 `1.33 m/s` 上限，不把整车永久限成低速。
6. 动态检查区分“当前/持久实测占用”与“未来运动预约”。普通规划仍使用保守预约并集；显式动态让行分支按同一时间检查运动轨迹，可选择制动等待或有界倒车后停车。实际占用、地形碰撞、未知支撑和概率预算均不能忽略。默认执行延迟 `0.35 s`、最小制动减速度 `1.2 m/s²` 未调低；倒车预测必须先经历原方向减速，不能瞬时反向。
7. 普通命令制动检查补上换向时的双向包络：实际仍前行而收到倒车命令时，前方制动距离不能消失。两方向共同使用一个风险预算；这仍是保守运动模型，不是任意动力学误差下的制动证明。

动态分支状态、运动目标数量、计算耗时和实际认证上界会发布到 `/terrain_nav/chance_status` 并进入资格原始记录。缺少认证时记录拒绝，不写成零风险。记录器同时修复了 ROS `DiagnosticStatus.level` 在本环境以单字节值返回导致 JSON 保存失败的问题。

概率阈值 `0.05 / 0.10 / 0.05`、姿态及台阶限制不变。FAST-LIO2 配置和降采样参数未在本轮修改。

## 受控场景

坡面为四米长平滑坡段，而不是突然抬升的挡板：

\[
u=\operatorname{clip}((x-1.5)/4,0,1),\qquad z=-0.02+h(3u^2-2u^3).
\]

最大坡角为 `atan(1.5*h/4)`，默认抬升 `h=0.45 m` 对应约 `9.58°`；`h=0.90 m` 对应约 `18.65°`。
这是场景几何，不是宣称车辆能在任意同角度地面上通过。路面摩擦、车身姿态、台阶、支撑和转弯几何仍分别约束导航。

| 场景 | 任务 |
| --- | --- |
| `staggered` | 平路三根错列柱子，前方 12 m 目标 |
| `crossing` | 平路动态横穿后继续到达 |
| `ramp_detour` | 坡中圆柱绕行，上坡和下坡分别测试 |
| `ramp_crossing` | 圆柱在实际坡面上横穿，上坡和下坡分别测试 |
| `ramp` | 无中央障碍坡道，可加横向目标检验爬坡与转弯耦合 |

坡面动态圆柱位于世界 `x=3.5 m`，半径 `0.65 m`、高 `1.8 m`，在 `2.4 s` 内从 `y=3.2 m` 横穿到 `-3.2 m`。
默认沿起始车头方向实际前进 `2 m` 后触发；下坡从世界 `x=7 m`、车头 `180°` 启动，不能用绝对世界 X 直接触发。
碰撞体和障碍真值使用同一坡面高度。几何仅用于仿真和独立评价，不传给规划器。

## 指标含义

- 实际到达并停稳：独立真值距目标不超过 `0.30 m`，实际速度低于 `0.05 m/s`、命令速度低于 `0.03 m/s`，持续 `0.5 s`。
- 车身净距：实际有向车身包络与柱子/墙的平面距离，前伸 `0.58 m`、后伸 `0.48 m`、半宽 `0.40 m`。不是车辆中心距离。门限 `0.10 m`，负值表示包络重叠；采样检查不是连续三维无接触证明。
- 动态威胁成立：冻结事件前实际速度和朝向，检查不响应时的投影是否进入障碍危险范围。障碍只是远处移动不算完成近距离动态资格。
- 响应：从障碍首次运动到零速命令、持续实际停稳的模拟时间。零速命令延迟要求不超过 `0.6 s`；停车后仍必须满足全程净距和最终到达，不能把“停住后被撞”算成功。
- 坡面覆盖：默认资格检查实际上升/下降至少 `0.28 m`，俯仰不超过 `0.55 rad`、横滚不超过 `0.45 rad`。场景脚本支持更低抬升，但小于 `0.28 m` 的坡不能套用该完整坡段验收。
- 运行时效：运动全窗口风险图至少 `5 Hz`，接收时源年龄最大 `0.35 s`，LiDAR / IMU 壁钟吞吐不低于额定的 `95%`。源年龄不是两帧间控制器持有旧图的最大年龄；控制器另有过期停车保护。

本轮属于小规模定向资格测试，不是正式统计成功率实验。失败原始结果保留，不能只汇总成功运行。

## 复现命令

每次只运行一个自动检查，脚本负责四模块启动和自有进程清理：

```bash
python3 scripts/sim/checks/pipeline_smoke.py --domain 89 \
  --prediction-backend feature_sgp --gp-complete-supported \
  --probability-model shared_gp --gp-support-distance .75 \
  --startup-support stable_stance --reverse-recovery \
  --trial-scenario ramp_crossing --require-dynamic-encounter --trial-timeout 60
```

下坡追加 `--ramp-direction downhill`；更陡坡追加 `--ramp-rise .9`。
`ramp_detour` 与 `ramp` 不使用 `--require-dynamic-encounter`。
无界面资格不等于当前 GUI 渲染性能或 RViz 截图资格，两者不能混称。

人工查看同一场景时，按顺序在四个终端启动，避免同时运行自动检查：

```bash
scripts/sim/start_simulation.sh --scene-profile light --map-asset none \
  --nav-test-scenario ramp_crossing --nav-test-ramp-rise .45

scripts/sim/start_mapping.sh rviz:=false

scripts/sim/start_terrain_analysis.sh terrain_backend:=gpu fsgp_gpu_backend:=cupy \
  prediction_backend:=feature_sgp gp_device:=cuda probability_model:=shared_gp \
  gp_complete_supported:=true probability_gp_max_distance_m:=.75 startup_support_mode:=stable_stance

scripts/sim/start_planning_control.sh chance_allow_gp_completion:=true \
  chance_allow_joint_model:=true chance_allow_startup_prior:=true reverse_recovery_enable:=true
```

随后在共享 RViz 中设置目标。动态圆柱由车辆实际前进触发；不要同时开键盘控制发布 `/cmd_vel`。

## 尚未达到的目标

目前只打通了上述限定场景，不是“非平坦通用导航已完成”。较陡下坡和原失败的侧向目标现已各取得到达记录，但下一步仍需优先改善约 43..45 秒的低速停行/绕行效率，检查风险图时变及坡中保持，并提高动态横穿的最小净距余量。历史失败图还显示部分零速命令期间存在小幅实际下滑，不能只修改规划器便宣称整车坡中制动已解决。

随后再覆盖多个独立动态目标、加速/反向横穿、部分遮挡、连续目标切换、未知断崖/窄台阶、较陡坡近障和不同摩擦条件。当前让行模型为短时恒速平移，初始假设与联合 GP 模型也没有实车校准；这些限制不能从配置文件中删除或用“概率安全”掩盖。正式批量实验仍需审阅协议。
