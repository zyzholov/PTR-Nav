# NMPC 轨迹跟踪控制原理

## 一、我们要解决什么问题？

### 1.1 问题描述

规划器给我们一条轨迹——一系列带时间戳的 (x, y, θ, v) 点。我们的任务是: **让车辆沿着这条轨迹走，尽可能走准。**

```
规划器输出的轨迹:
    ●───●───●───●───●───●───●───●───●───●
    t=0  t=0.1  t=0.2  ...        t=1.0

车辆实际要做的:
    在 t=0 时刻到达第一个点
    在 t=0.1 时刻到达第二个点
    ...
    在 t=1.0 时刻到达最后一个点
```

### 1.2 为什么不用 PID？

PID 是最简单的跟踪控制器:

```
steer = Kp × 横向误差 + Ki × 误差积分 + Kd × 误差微分
```

PID 的问题:
- **只看当前误差**: 不知道前方有弯道，等到偏离了才纠正
- **不考虑约束**: 转向角可能超出物理极限
- **不考虑动力学**: 高速时急转会导致侧滑
- **倒车困难**: 需要完全不同的控制逻辑

### 1.3 MPC 的核心思想

MPC (Model Predictive Control，模型预测控制) 的思想是: **不要只看当前，要看未来。**

```
PID 的思路:
    现在偏了 → 纠正

MPC 的思路:
    我预测未来 1 秒内会怎么走
    → 在这 1 秒内找一组最优的控制动作
    → 只执行第一个动作
    → 下一帧重新预测、重新优化
```

**类比:**
- PID 像开车时只看车头前方 1 米
- MPC 像开车时看前方 50 米，提前规划好怎么转弯

## 二、MPC 的工作循环

### 2.1 一个控制周期内发生了什么

每隔 40ms (25Hz)，MPC 执行一次:

```
时刻 t:
│
├─ 1. 测量: 车辆现在在哪？朝向哪？ (从里程计获取)
│         → x = 3.2m, y = 1.5m, θ = 0.3 rad
│
├─ 2. 采样: 未来 1 秒内，参考轨迹在哪？
│         → ref[0] = (3.3, 1.6, 0.35)  // 0.1s 后
│         → ref[1] = (3.4, 1.7, 0.40)  // 0.2s 后
│         → ...
│         → ref[9] = (4.0, 2.5, 0.80)  // 1.0s 后
│
├─ 3. 优化: 找一组 (v, δ) 序列，让车辆沿参考走
│         → 求解一个优化问题
│         → 得到最优控制序列: [(v₀,δ₀), (v₁,δ₁), ..., (v₉,δ₉)]
│
├─ 4. 执行: 只执行第一个动作
│         → 发送 v₀, δ₀ 给车辆
│
└─ 5. 等待: 等 40ms，回到步骤 1
```

### 2.2 为什么要"只执行第一个动作"？

因为我们每 40ms 都会重新测量、重新优化。如果执行多个动作，中间的环境变化就无法应对。

```
t=0:  预测未来 → 执行 u₀
t=40ms: 重新测量 → 重新预测 → 执行 u₀'
t=80ms: 重新测量 → 重新预测 → 执行 u₀''
...

这就是"滚动时域" (Receding Horizon) 的含义:
    时域窗口不断向前滚动，每一步都重新优化
```

## 三、车辆怎么运动？—— 自行车模型

### 3.1 为什么要关心车辆模型？

MPC 需要 **预测** 车辆未来的运动。预测需要一个数学模型——"如果我现在给车辆一个速度 v 和转向角 δ，下一秒它会到哪里？"

### 3.2 自行车模型的直觉

把四轮汽车简化为两轮自行车:

```
        前轮 (可转向)
           ╱
          ╱ δ
         ╱
    ────●────────────
    │       L (轴距)
    │
    ────●────────────
        后轮 (固定)
```

**关键观察:**
- 车辆绕后轴中心旋转
- 转向角 δ 决定了转弯半径
- 速度 v 决定了运动快慢

### 3.3 运动方程

```
位置变化:
    dx/dt = v × cos(θ)      // x 方向速度分量
    dy/dt = v × sin(θ)      // y 方向速度分量

航向变化:
    dθ/dt = v × tan(δ) / L  // 航向角变化率
```

**第三个公式的直觉:**
- `v × tan(δ)` 是车辆"转圈的线速度"
- 除以 `L` 得到角速度
- 转向角越大 → 转弯越急
- 速度越快 → 转弯越急 (同样的转向角，高速转弯半径更大)

### 3.4 从连续到离散

计算机不能处理连续时间，需要离散化。用最简单的"前向欧拉":

```
x_{k+1} = x_k + dt × v_k × cos(θ_k)
y_{k+1} = y_k + dt × v_k × sin(θ_k)
θ_{k+1} = θ_k + dt × v_k × tan(δ_k) / L
```

**含义:** 知道当前状态 (x_k, y_k, θ_k) 和控制量 (v_k, δ_k)，就能算出下一时刻的状态。

这就是 MPC 预测未来的基础。

## 四、MPC 优化什么？—— 代价函数

### 4.1 核心问题

给定当前状态和未来 N 步的参考轨迹，找一组控制量 (v₀,δ₀), (v₁,δ₁), ..., (v_{N-1},δ_{N-1})，使得 **跟踪误差最小**，同时 **控制量不要太大、变化不要太剧烈**。

### 4.2 代价函数的三项

```
J = 跟踪误差 + 控制代价 + 平滑代价
```

#### 第一项: 跟踪误差

```
J_track = Σ Qx×(ref_x - x)² + Qy×(ref_y - y)² + Qθ×(ref_θ - θ)²
```

**含义:** 车辆位置和航向要尽量接近参考。

权重的物理意义:
- `Qx = Qy = 100`: 位置误差惩罚重 → 车辆必须沿着参考路径走
- `Qθ = 10`: 航向误差惩罚轻 → 位置对了，航向自然对

#### 第二项: 控制代价

```
J_control = Σ Rv×(ref_v - v)² + Rδ×(ref_δ - δ)²
```

**含义:** 控制量尽量接近参考控制量。

权重的物理意义:
- `Rv = 0.10`: 速度偏差惩罚轻 → 允许 MPC 自由调速
- `Rδ = 0.01`: 转向偏差惩罚极轻 → 允许 MPC 自由调转向

**为什么 R 这么小？** 因为我们更关心"位置对不对"，而不是"速度和转向是否和参考一样"。如果参考说要直走，但车辆偏了，MPC 应该自由地调整转向来纠正，而不是死板地跟着参考的转向角。

#### 第三项: 平滑代价

```
J_smooth = Σ Rdv×(v_k - v_{k-1})² + Rdδ×(δ_k - δ_{k-1})²
```

**含义:** 控制量变化不要太剧烈。

权重的物理意义:
- `Rdv = 8`: 加速度不要突变 → 乘坐舒适
- `Rdδ = 20`: 转向不要突变 → 保护转向机构

### 4.3 完整代价函数

```
J = Σ_{k=0}^{N-1} [
      Qx × (ref_x - x_k)²
    + Qy × (ref_y - y_k)²
    + Qθ × (ref_θ - θ_k)²
    + Rv × (ref_v - v_k)²
    + Rδ × (ref_δ - δ_k)²
    + Rdv × (v_k - v_{k-1})²
    + Rdδ × (δ_k - δ_{k-1})²
]
```

**这是一个二次函数 (Quadratic Function)。** 如果没有约束，它有解析解。但因为有约束 (速度限制、转向角限制)，需要数值求解。

### 4.4 约束条件

```
速度约束:    v_min ≤ v_k ≤ v_max
转向角约束:  -δ_max ≤ δ_k ≤ δ_max
动力学约束:  x_{k+1} = f(x_k, v_k, δ_k)   // 必须满足自行车模型
初始状态:    x_0 = 测量到的当前状态
```

**约束的物理含义:**
- 速度不能超过最大速度 (物理极限)
- 转向角不能超过最大转向角 (机械极限)
- 车辆运动必须符合物理规律 (不能瞬移)

## 五、怎么求解？—— CasADi + SQP

### 5.1 问题形式

把上面的内容写成标准形式:

```
minimize    J(x, u)
subject to  x_{k+1} = f(x_k, u_k)      // 动力学等式约束
            x_0 = x_measured             // 初始状态约束
            u_min ≤ u_k ≤ u_max         // 控制量盒约束
```

这是一个 **带约束的非线性优化问题**。

### 5.2 为什么是非线性的？

因为自行车模型包含 `cos(θ)` 和 `tan(δ)`——这是非线性函数。

```
x_{k+1} = x_k + dt × v_k × cos(θ_k)    // cos 是非线性的
θ_{k+1} = θ_k + dt × v_k × tan(δ_k)/L  // tan 是非线性的
```

如果模型是线性的 (比如 `x_{k+1} = A×x_k + B×u_k`)，就可以用 QP 求解器，速度快得多。但非线性模型更准确，特别是在大转向角时。

### 5.3 SQP 算法的直觉

SQP (Sequential Quadratic Programming，序列二次规划) 的思想:

```
迭代 1:
    在当前猜测点，把非线性问题近似为二次问题 (QP)
    求解这个 QP → 得到一个更好的猜测点

迭代 2:
    在新的猜测点，重新线性化
    再求解一个 QP → 得到更更好的猜测点

...

迭代 N:
    收敛到最优解
```

**类比:** 像是在山谷中找最低点——每次看脚下最陡的方向，走一步，再看，再走。

### 5.4 热启动

相邻两个控制周期的最优解通常很接近。所以用上一周期的解作为这一周期的初始猜测:

```
上一周期的解:  u = [u₀, u₁, u₂, ..., u₉]

热启动:
    u_init = [u₁, u₂, ..., u₉, u₉]  // 右移一步
```

这样 SQP 通常 3-5 步就收敛 (没有热启动可能需要 20+ 步)。

### 5.5 求解失败怎么办？

有时候优化问题无解 (比如参考轨迹穿墙了)。这时候切换到简单的比例控制器:

```
// 计算到参考点的方向和距离
target_yaw = atan2(ref_y - y, ref_x - x)
dist = sqrt((ref_x - x)² + (ref_y - y)²)

// 比例控制
v_fallback = 0.5 × dist × cos(heading_error)
δ_fallback = 0.9 × heading_error

// 与上一周期混合 (平滑过渡)
v = 0.5 × v_fallback + 0.5 × v_prev
δ = 0.55 × δ_fallback + 0.45 × δ_prev
```

这是保底策略——不如 MPC 精确，但至少能让车辆朝目标移动。

## 六、参考轨迹怎么处理？

### 6.1 采样

从规划器的轨迹中，每隔 0.1s 采样一个点，共采样 N=10 个点:

```
当前时刻 t
    │
    ├── t + 0.1s → ref[0] = (x, y, θ, v, κ)
    ├── t + 0.2s → ref[1] = (x, y, θ, v, κ)
    ├── ...
    └── t + 1.0s → ref[9] = (x, y, θ, v, κ)
```

每个参考点包含: 位置 (x,y)、航向 θ、速度 v、曲率 κ。

### 6.2 参考控制量怎么算？

从参考点反算参考控制量:

```
ref_v = 参考轨迹给出的速度

ref_δ = atan(L × κ)    // 从曲率反算转向角
```

**曲率 → 转向角的推导:**
```
自行车模型: κ = tan(δ) / L
反解:       δ = atan(κ × L)
```

### 6.3 航向连续化

参考轨迹的航向角可能有 2π 跳变:

```
问题:
    ref[0].θ = 3.0 rad
    ref[1].θ = -3.0 rad    // 看起来差了 6 rad!
    实际上只差 0.28 rad    // 只是因为跨过了 ±π 边界
```

**解决方法:**
```
相邻参考点的航向差限制在 [-π/2, π/2] 内

while (ref[k+1].θ - ref[k].θ) > π/2:
    ref[k+1].θ -= 2π
while (ref[k+1].θ - ref[k].θ) < -π/2:
    ref[k+1].θ += 2π
```

### 6.4 滑动时间参考

车辆不一定严格按照参考轨迹的时间线运动。如果车辆落后了，参考应该"等"车辆:

```
// 找到车辆在参考轨迹上的最近点
nearest_t = 找最近点的时间

// 参考时间不能比车辆当前位置超前太多
if 参考时间 > 最近时间 + 0.55s:
    参考时间 = 最近时间 + 0.35s

// 参考时间只能前进，不能后退
参考时间 = max(参考时间, 上一次的参考时间)
```

## 七、后处理：从优化解到实际控制

MPC 求解出来的 (v, δ) 不能直接发给车辆，需要经过后处理:

### 7.1 限幅

```
v = clamp(v, -0.18, 0.95)           // 速度限制
δ = clamp(δ, -0.5236, 0.5236)       // 转向角限制
```

### 7.2 变化率限幅

```
// 每步最大变化量
max_Δv = 1.10 × 0.10 = 0.11 m/s    // 加速度限制
max_Δδ = 4.00 × 0.10 = 0.40 rad    // 转向速率限制

// 不能比上一步变化太大
v = clamp(v, v_prev - 0.11, v_prev + 0.11)
δ = clamp(δ, δ_prev - 0.40, δ_prev + 0.40)
```

**为什么需要这个？** 优化解可能要求瞬间加速或急转，但物理上做不到。变化率限幅保证控制量平滑过渡。

### 7.3 转弯减速

```
// 转向角越大，速度越低
steer_ratio = |δ| / δ_max
v_cap = v_max × (1 - 0.36 × steer_ratio)

示例:
    直行 (δ=0):     v_cap = 0.95 m/s
    小转 (δ=15°):   v_cap = 0.78 m/s
    满转 (δ=30°):   v_cap = 0.61 m/s
```

**物理原因:** 转弯时侧向加速度 `a_lat = v² × κ`，速度越高侧向力越大，容易打滑。

### 7.4 曲率限速

```
// 保证侧向加速度不超过 0.45 m/s²
v_cap = sqrt(0.45 / |κ|)
```

### 7.5 Stanley 转向辅助

当跟踪误差大时，MPC 的转向修正可能不够快。叠加一个几何修正:

```
// 横向误差 (体坐标系)
ey = 车辆到参考线的垂直距离

// Stanley 修正: 误差越大，转向越大
δ_stanley = atan2(k × ey, v)

// 与 MPC 的转向混合
δ_final = (1-blend) × δ_mpc + blend × δ_stanley
```

**类比:** 像骑自行车时，偏离路线越多，转把幅度越大。

### 7.6 倒车处理

倒车时模型行为变化:

```
前进: v > 0, 转向角 δ → 车头转向
倒车: v < 0, 转向角 δ → 车尾转向 (效果相反)
```

MPC 内部通过自行车模型自然处理了这个反转。但后处理需要额外逻辑:
- 检测参考轨迹是否要求倒车
- 如果要求倒车，确保速度为负
- 防止前进/倒车频繁切换 (0.8s 冷却期)

## 八、权重矩阵怎么调？

### 8.1 权重的直观理解

```
Q (状态跟踪):  "位置有多重要？"
    Q 越大 → 车辆越紧贴参考路径 → 但可能控制量变化大

R (控制偏差):  "控制量有多重要？"
    R 越大 → 控制量越接近参考 → 但可能跟踪误差大

Rd (控制平滑): "控制量变化有多重要？"
    Rd 越大 → 控制越平滑 → 但可能跟踪响应慢
```

### 8.2 调参经验

```
第一步: Q 设大，R 设小
    → 让 MPC 全力跟踪，看能不能跟上
    → 如果跟上了，说明模型和约束没问题

第二步: 逐步增大 Rd
    → 让控制变平滑
    → 观察跟踪误差是否增大到不可接受

第三步: 微调 Q 和 R 的比例
    → 如果转向太频繁: 增大 Rd_δ
    → 如果速度波动大: 增大 Rd_v
    → 如果位置跟踪差: 增大 Q_x, Q_y
```

### 8.3 本工程的权重配置

```
Q = diag(100, 100, 10)     // 位置跟踪权重高
R = diag(0.10, 0.01)       // 控制偏差权重极低
Rd = diag(8.0, 20.0)       // 转向平滑权重 > 速度平滑权重
```

**设计哲学:**
- 位置必须跟准 (Q 大)
- 控制量可以自由调整 (R 小)
- 转向要平滑 (Rd_δ 大)

## 九、预测时域的选择

### 9.1 预测时域的影响

```
预测时域太短 (比如 0.3s):
    ├─ 只看到眼前
    ├─ 来不及应对前方的弯道
    └─ 可能"冲出弯道"

预测时域太长 (比如 5s):
    ├─ 计算量大
    ├─ 远处的参考点不确定性大
    └─ 可能"过度规划"

预测时域适中 (1.0s):
    ├─ 能看到前方的弯道
    ├─ 计算量可控
    └─ 平衡了预见性和实时性
```

### 9.2 本工程的选择

```
N = 10 步, dt = 0.10s
预测时域 = N × dt = 1.0s
```

**为什么是 1.0s？**
- 车辆最大速度 0.95 m/s → 1s 内最多走 0.95m
- 这个距离足够看到前方的弯道和障碍物
- 10 步的计算量在 10ms 内可完成

## 十、与线性 MPC 的对比

### 10.1 为什么不用线性 MPC？

线性 MPC 把自行车模型线性化:

```
非线性:  θ̇ = v × tan(δ) / L

线性化:  θ̇ ≈ v × δ / L        (当 δ 很小时)
```

线性 MPC 的优势:
- QP 求解器很快 (~1ms)
- 理论成熟，容易调参

线性 MPC 的劣势:
- 大转向角时误差大
- 倒车时需要特殊处理
- 速度变化大时需要重新线性化

### 10.2 本工程的选择

选择非线性 MPC 的原因:
- 车辆需要大转向角 (30°)，线性化误差大
- 需要支持倒车
- 低速时线性化更不准 (v 小，tan(δ)/L 近似更差)
- 10ms 求解时间满足 40ms 控制周期

## 十一、控制效果怎么看？

### 11.1 跟踪误差

```
横向误差:  车辆到参考线的垂直距离
纵向误差:  车辆沿参考线方向的前后偏差
航向误差:  车辆朝向与参考朝向的差角
```

**好的跟踪:**
- 横向误差 < 0.15m
- 航向误差 < 0.15 rad (≈8.6°)

### 11.2 可视化判断

在 RViz 中:
- **参考路径** (红-蓝渐变): MPC 要跟踪的目标
- **预测路径** (绿色): MPC 预测的未来轨迹
- **车辆历史** (橙红色): 车辆实际走过的路径
