# 地形补全与非平坦导航修正记录（2026-10-24）

## 目的与结论边界

本次工作优先解决“引入补全后反而不能导航”，不是让地图看起来填满。
运行对象为 Isaac 实际轮地接触动力学下的完整传感、定位、地形、规划和控制链路：

`LiDAR / 外置 IMU -> FAST-LIO2 -> 地形统计前端 -> 条件共享 GP / BGK / SEB -> 概率约束滚动规划 -> 混合跟踪控制 -> 底盘`

前端构建实测高程、方差和障碍证据；GP 提供有限观测支撑内的相关高程后验；SE(2) 几何检查将其转成车身姿态失效上界；规划器同时检查整段路径、制动和实测碰撞。
GPU 是这些计算的实现后端，不是额外的一套地形理论。跟踪器仍是 Pure Pursuit / Stanley 混合控制，不是 MPPI。

`shared_gp` 是本工程的条件共享场适配，不是原论文代码的逐位复现，也不是实车已校准概率。
起始稳定支撑假设仍须显式启用，仅固定在仿真起始足迹内，不随车移动。实车和完全未知模式不自动放行。
本次是逐问题的小规模定向资格检查，包含失败和混合修订，不是批量成功率实验；没有运行外部方法对比，没有提交或推送 GitHub。

## 方法与实现修正

### 共享高程后验的粗糙度界

足迹高度采用同一个相关后验，而不是把每个高度当作独立随机数：

\[
h\sim\mathcal N(\mu,BB^T+\delta^2R).
\]

对任意高度对比系数 \(c\)，均值为 \(c^T\mu\)，标准差保守取为

\[
\sigma_c=\sqrt{\alpha(\|B^Tc\|^2+\delta^2c^TRc)}
              +\|c\|_1\sigma_{\mathrm{floor}}.
\]

这里 \(R\) 为模型假设的空间相关结构，最后一项不要求传感器底噪相互独立；这仍依赖条件场模型，并非现实失效概率的经验校准。

设 \(r_i\) 是足迹内拟合平面后的高度残差，物理粗糙度事件为
\(\max_i r_i-\min_i r_i>H\)，其中 \(H=0.18\,\mathrm m\) 不变。
原先只使用一个较强的充分条件，现在同时计算两个有效并合上界：

\[
U_{\mathrm{half}}=\sum_iP(|r_i|>H/2),\qquad
U_{\mathrm{pair}}=\sum_{i<j}P(|r_i-r_j|>H).
\]

采用 \(\min(U_{\mathrm{half}},U_{\mathrm{pair}})\)，再与俯仰、横滚和内部高度突变事件合并。
这是对同一失效事件的证明收紧，不是增大可通过台阶、降低方差或取消未知检查；事件之间不相乘。
CPU 与融合 CUDA 均已实现，CUDA 仅对非平凡查询计算成对界，分批限制临时显存。

两帧真实冻结输入的回放中，后验均值与存档最大差均为零，查询支撑集合不变。
较陡下坡帧中，9172 个可评估姿态里满足 0.05 状态门限的数量从 8510 增至 9172；另一帧 9876 个姿态的准入数量不变。
这只证明同一后验上的两个界及其实现关系，不是独立导航成功率或实车安全校准。
原始数组、输入哈希和计时见 `log/shared_certificate_frozen_20261024/`。

### 观测一致性与障碍物角色

1. GP 训练似然使用至少 2 cm 的观测标准差，而原观测一致性门限可能只按前端的 1 cm 标准差取 3 cm。现在使用同一个似然噪声下界：
   \(t=\min(0.05,\max(0.03,2\sqrt{\max(v,\sigma_n^2)}))\)，单位为米。默认门限为 4 cm；6 cm 偏差、明显台阶和原始否决仍不能通过。没有增大 GP 噪声、缩小后验方差或删除实测。
2. 柱顶即便高度方差很小，也不能自行充当地面参考。CPU、CUDA 和原生实时障碍层现在均检查实测邻域中的较低地面；连续斜坡与突起分别处理。
3. 新旧地面参考得到的上方障碍证据取并集，不能因改选较低参考后触发高度上限而抹掉旧障碍。
4. 实时障碍层对有实测地面支持的单个上方返回立即响应。无地面参考的孤立点不凭空创造地面；高悬返回仍按原高度范围处理。
5. 仿真默认关闭“同一 XY 格收到两次地面就提前清除上方障碍”的路径。二维地面可见不证明同格细柱消失。保留原有 1 秒有限障碍保持期；这仍不是完整三维可见性清除证明。

状态 / 局部路径 / 制动门限仍分别为 `0.05 / 0.10 / 0.05`；俯仰 `0.55 rad`、横滚 `0.45 rad`、台阶 `0.18 m` 不变。
本次没有修改 FAST-LIO2 配置或降采样参数。

### 有界退让与恢复导航

车辆有时未碰撞，但额外实时障碍膨胀层覆盖当前足迹，普通规划的所有起始原语便会被拒绝。
新增分支仅允许退出这部分额外预约空间，不能退出真实碰撞检查：

- 起步须停稳、输入新鲜、后方有合格支撑；存在动态轨迹时不使用该静态预约退让分支。
- 使用未额外膨胀但保留历史保持期的真实占用，仍检查完整车身及 `0.10 m` 配置余量。
- 全程额外膨胀重叠格数量不能超过初始值，终点必须重新满足正常膨胀检查及硬净距限制。
- 退让限速 `0.30 m/s`，候选为 `0.12 / 0.25 / 0.40 / 0.60 / 0.90 m`；保留执行延迟、制动模型和全部概率检查。
- 每个控制周期重新认证剩余轨迹；输入过期、目标变更、时间回退均停车。必须实际停稳，并获得更新地图上的释放确认后，才结束退让、请求正常规划。
- 短退让和普通倒车换姿恢复分别最多两次每目标，合计最多四次。两者不能互相耗尽计数；重复发送同一目标不能重置计数。次数增加不是碰撞或概率门限放宽，也不是整任务失效概率保证。
- 普通规划已失败时，恢复触发检查覆盖车身周边 2.6 m 的实时障碍，而不是只检查前方中心窄带。侧方障碍也可能封住转弯空间；扩大触发范围不等于允许任何未认证机动。

这与动态横穿时的制动等待/时序避让分支不同。当前物理动态成功案例不能替代“动态倒车逃逸”分支的实车或仿真资格。

专项 `reserve_overlap` 先让车辆正常前进约 2.12 m、实际停车，再将有碰撞体的箱体移到额外预约区，随后给出新的前方目标。
这样后方来自真正扫描/行驶过的地面，不是假设一个跟车移动的安全区。准备阶段和主导航分别保存真值、时间和障碍位姿。
验收必须在同一段认证退让开始至 `completed` 之间测到实际后退，不能把后续其他控制器的倒车计入该分支。

## 时效优化与诊断

FSGP 节点独立限制 OpenBLAS / OMP / MKL 线程，默认一线程，避免小矩阵并行争抢；可用 `HUNTER_FSGP_CPU_THREADS` 显式调整，不改变 Isaac 或 RViz 的全局线程环境。
规则栅格的历史证据寻址改为整数坐标，避免每帧重复构造整图 Python 字典；不规则输入保留原路径，连续实测清除与遮挡重置规则不变。

台阶检测融合成一个 CUDA 核，保留 CPU 公式、缺测和边界行为。
固定 104×104 数组上，十次交替暖态检查的单算子耗时由约 1.7 ms 降到约 0.03 ms，最大数值差约 `1.2e-7`。
这是实现检查，不是十个独立地形实验，也不意味着完整流水线快了几十倍；原始计时见 `log/observed_step_fusion_20261024.json`。

仅降低算子耗时仍不足以消除较陡坡道上的长尾，因此仿真 GPU 入口新增：

```text
fsgp_max_input_source_age_sec:=0.16
fsgp_max_output_source_age_sec:=0.30
```

过旧输入不占用下一次处理名额；计算完成却超过输出期限的结果不发布。源时间戳不改写，丢帧会记录。
通用节点、通用 launch 及 CPU 仿真入口默认均为零，即关闭该额外准入门限；CPU 托底不等于取得 GPU 实时资格。
参数可显式覆盖为零进行诊断，但不能因此免除控制器过期停车检查。

`/car_0_fsgp_bgk/runtime` 包含输入/输出源年龄、分阶段计算时间、`result_published`、累计输入/输出丢帧数。
`/terrain_nav/chance_status` 包含控制认证结果、动态避让状态、退让状态和两类恢复计数。

必须区分：

- 接收源年龄：接收到地图时，当前模拟时间减地图原始传感时间。
- 更新间隔：两次实际收到地图之间的壁钟时间。
- 更新前持有旧图年龄：新图到来前，控制器持有的上一张图已多旧。它通常比新图接收源年龄更大。
- 丢帧：真实没有发布的结果，不算新鲜地图，也不计入地图更新频率。

运动全窗口仍检查风险图至少 `5 Hz`、接收最大源年龄不超过 `0.35 s`、传感器壁钟吞吐至少额定的 `95%`。
控制器的 `0.50 s` 过期停车保护保持开启。通过前述有限资格并不证明每次控制周期都满足硬实时期限。

## 复现入口

四个终端按顺序启动，地图、规划与底盘仍按模块分开。以下是授权仿真条件模型的示例，不用于实车：

```bash
# 1. 环境、实际动力学与传感器
scripts/sim/start_simulation.sh --scene-profile light --map-asset none \
  --nav-test-scenario ramp_crossing --nav-test-ramp-rise .45

# 2. 定位建图，不再启动第二个 RViz
scripts/sim/start_mapping.sh rviz:=false

# 3. 地形分析、补全与共享 RViz
scripts/sim/start_terrain_analysis.sh terrain_backend:=gpu fsgp_gpu_backend:=cupy \
  prediction_backend:=feature_sgp gp_device:=cuda probability_model:=shared_gp \
  gp_complete_supported:=true probability_gp_max_distance_m:=.75 startup_support_mode:=stable_stance

# 4. 规划控制
scripts/sim/start_planning_control.sh chance_allow_gp_completion:=true \
  chance_allow_joint_model:=true chance_allow_startup_prior:=true reverse_recovery_enable:=true
```

在共享 RViz 设置目标，不要另开键盘控制同时发布 `/cmd_vel`。
`light / map-asset none` 是受控资格场景，不能用其性能宣称默认全纹理 Mars 场景同样不卡顿。
GUI 的高程模式、风险模式、累计点云和来源模式是不同视图；没有合法支撑的空白仍是未知，不为了显示连贯而画成可通行。

单个自动资格检查会自行启动和清理这四个模块，不要与人工启动混用：

```bash
python3 scripts/sim/checks/pipeline_smoke.py --domain 89 --gui --rviz-view height \
  --prediction-backend feature_sgp --gp-complete-supported --probability-model shared_gp \
  --gp-support-distance .75 --startup-support stable_stance --reverse-recovery \
  --trial-scenario ramp --ramp-direction downhill --ramp-rise .9 --goal-lateral -1.0 --trial-timeout 65
```

动态专项改为 `--trial-scenario ramp_crossing --ramp-direction downhill --require-dynamic-encounter --capture-motion-grid`，去掉 `.9` 抬升和侧向目标参数。
静态错列柱为 `--trial-scenario staggered`；预约退让专项为 `--trial-scenario reserve_overlap`。
`reserve_overlap` 仅用于专项准备和计数验证，不是推荐的日常场景。

## 尚未覆盖

条件概率尚未完成跨真实地形和失效标签的校准；还不能宣称全地形、高速度或多运动目标导航达到极高成功率。
实时障碍保持期不等于三维可见性清除，静态障碍不能因只看到下方地面而被擦除；长期遮挡与残影清除仍需成对测试。
当前 LiDAR 是可运行的扫描替代配置，没有真实 MID360 的完整逐点时序，不能将其结果等同于真实雷达验证。
所有净距均为明确几何体上的采样车身包络检查，不是连续三维无碰撞证明，也未把全部背景设施纳入专项真值净距。

后续批量方案应分别覆盖输入缺测、概率校准、可通过坡度/台阶、恢复机动、动态横穿和地图过期。
固定场景、传感条件和评价脚本后再开展重复试验；外部基线与自身消融分开记录，仍需方案审阅后执行。
不应在已定位为支撑角色、证明保守性或恢复逻辑的问题上，直接换一个未经校准的学习网络并宣称问题解决。
