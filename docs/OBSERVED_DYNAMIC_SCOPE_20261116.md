# 当前观测范围下的动态避障（2026-11-16）

按本次要求，当前阶段只处理有当前测量的动态目标，不再因为目标进入盲区而持续锁住导航。**这项范围修改已实现，但动态导航仍未达标。** 本次没有提交或推送 GitHub。

## 行为与启动方式

仿真 `hunter_gazebo.yaml` 已显式设置 `dynamic_observed_only: true`。也可明确启动：

```bash
scripts/sim/start_planning_control.sh navigation_profile:=neos_joint_sim dynamic_observed_only:=true
```

这是规划控制模块的命令；仿真、定位建图、地形分析按原四模块顺序先启动。`dynamic_observed_only:=false` 恢复保留未解除目标冲突的策略；`auto` 遵从传入的 YAML。实车独立启动脚本未改，节点构造默认值仍为 false。

实际规则是：

1. 新扫描中只保留源时刻属于本帧的运动模型，去掉仅依靠旧观测滑行的模型。未来或非法源时间不被伪装成“已离开视野”，仍由有效性检查拒绝。
2. 完整输入新鲜时，已无当前观测的旧目标不再使动态冲突账本无限等待；传感器或地图断流不触发这种退出。
3. 正在执行避让而当前目标全部消失时，退出旧避让动作，交回普通规划控制。该退出本身不发布新的通行命令。重新测到的目标必须重新参与完整动作检查。
4. 原始/保留占据、车体包络、未知地面、制动及概率预算、输入时效检查继续生效。没有把目标原位置涂成安全地面。

“当前测量”是跟踪器的测量来源条件，**不是解析的可见性证明**。若视野内的目标漏检，运动模型也可能缺失；本修改不能证明目标一定在物理视野之外。它不提供盲区碰撞保证，且目前没有新增旋转雷达版本。

诊断 `/terrain_nav/chance_status` 增加 `dynamic_observed_only` 和 `dynamic_unobserved_conflicts_skipped`，启动日志也打印当前范围。

## 可见目标下仍然存在的问题

第一次单目标拒绝保存了源时刻匹配的风险图、条件点云、实时点云、附近里程计及完整后验。回放中使用记录的车辆根状态、根时刻之前实际发布的命令，以及记录的目标模型，不输入场景真值。通过生产 `timedYieldSafe` 检查筛选排名靠前的 16 条候选，均在动态风险阶段拒绝，尚未进入完整地形足迹阶段；最小独立动态上界约 0.0656，高于不变的 0.05 门槛。因此，这份来源的首次拒绝不能直接归咎于地形补全。

附加的转向/时长候选诊断也未在该来源下取得动态证明，因此未把它加入运行候选库。回放只保留了一帧几何，无法复原完整保留占据与源匹配运动所有权历史；使用新的独立抽样，也不是逐比特重演。它用于分离拒绝原因，不是整车成功证据。

可复用入口为 `build/terrain_nav/audit_frozen_map` 的 `dynamic_capture` 请求。单目标目录 `dynamic_refusal/` 中保留 `audit_request.json`、`reconstructed_parameters.yaml`、`production_proof_audit.json` 及动态候选诊断结果。重构参数明确不是运行时转储。
