# 导航实时性与动态避障资格记录

日期：2026-10-26。本记录对应本机实际 Isaac/ROS 整链试跑，不是论文批量实验，也不是实车安全认证。

## 1. 结论与边界

本次先按修正后的碰撞几何试跑，发现失败后修改，再用同一修订重复检查。共保留 17 个运行目录：16 次执行了任务的物理检查，以及 1 次发目标前主动终止的启动检查。失败和中止均未删除。

最终 C 修订的 8 次定向检查中，7 次完整通过，另 1 次虽然安全到达，但风险图时效超限，整链仍判失败。该计数包含一个“台阶应拒行”的负例，不能称为导航成功率，更不能由此宣称高成功率或通用导航已经达标。

本版已实测：平路动态横穿、上坡动态横穿、下坡动态横穿及其重复、三柱连续绕障及其重复、默认 Mars 渲染场景短程前进/倒车返回、不可通行台阶拒行。尚存在规划长尾和偶发地图时效抖动，不能将它们说成已解决。

## 2. 不变的验收条件

- 链路：Isaac 物理接触与传感器 → FAST-LIO → CUDA 地形前端 → CUDA 共享 GP / CuPy BGK-SEB → 规划与跟踪控制。控制不读取场景障碍物真值；真值仅供独立验收。
- 实体车身平面包络为前 0.58、后 0.48、半宽 0.40 米；仅加一次 0.10 米余量，保护总宽 1.00 米。没有为了通过测试缩小车身、关闭碰撞或使用位姿瞬移。
- 保持状态概率上限 0.05、局部路径预算 0.10、制动预算 0.05；保持俯仰 0.55、横滚 0.45 弧度和台阶 0.18 米限制。概率是当前模型条件下的上界，尚非实车经验校准的安全保证。
- 到达须同时停稳，独立真值目标误差不超过 0.30 米；相关专项/背景障碍的采样完整车身净距至少 0.10 米。采样净距不是连续三维网格碰撞证明，也不覆盖未记录的全部环境物体。
- 动态横穿额外要求：若车辆保持事件开始时的速度/航向，预测净距必须小于 0.10 米，证明这确实是冲突遭遇；零速命令须在事件开始后 0.60 秒内出现，还必须观察到实际停稳。远处物体移动不能冒充一次避障成功。
- 目标下发前先武装运动期数据监测。GPU 地图至少 5 Hz，接收时源时间年龄上限 0.35 秒；雷达和 IMU 墙钟吞吐至少达到标称的 95%。同时保留消息间隔和更新前持有地图的最大年龄，不把“有话题”当作实时。
- 明确启用仿真限定的固定稳定起始支撑和 0.75 米以内有实测支撑的补全，不允许假设区随车扩张，不将 GP 预测解释成观测到自由空间。实车不能直接启用此起始假设。
- 跟踪器仍为混合 Pure Pursuit/Stanley，不是 MPPI。传感器点云仍是 Ouster 扫描替代模型，没有真实 MID360 逐点时间，不能把这些测试称为真实 MID360 复现。

概率图源年龄、动态响应和任务历时使用模拟时钟；规划计算耗时、话题吞吐和首次控制命令延迟使用墙钟。这些量不能直接相加或混称为一个延迟。

## 3. 根据实测进行的修改

### A → B：减少关键链路阻塞和伪动态

早期一次真实冲突已避让并到达，但配准点云出现 0.365 秒、原生地形图出现 0.390 秒的源年龄，整链失败。FAST-LIO 改为在校正位姿发布后立即发布同一校正状态下的当前世界点云，再维护增量树和累计地图的可见性清理。没有改变两份 Hunter YAML 的降采样、滤波参数或删除累计地图。

运动关联改为连续两次一致平移后才确认速度，原始占据仍立即进入车身碰撞检查。冻结旧场景的掩码回放中，事件前伪运动帧由 11/78 降为 0/78，事件后静态段由 75/174 降为 7/174；真实事件段输出运动帧由 22/24 变为 20/24。这只是冻结输入诊断，不是独立目标检测召回率，也不是闭环成功率。

从 B 起逐个记录所有已完成规划任务的墙钟耗时，包括失败任务。A 的日志曾限频，不能使用其少量日志样本声称全任务 P95 改善。

### B → C：未确认运动先制动，不先放行动作

B 的下坡横穿出现 0.071 米净距，低于 0.10 米门限，判失败。分析发现，等待第二次平移确认延迟了制动。

C 对第一次合格平移证据新增短制动时域检查：只允许提前发送零速，不授权倒车、不清空原始占据、不修改概率地形或把候选变成长期障碍。正式动态制动/退让仍需已确认运动和原有安全检查。无冲突、证据过期、无目标时不能触发这一动作；新增原生回归覆盖了这些边界。

同条件的两次 C 下坡测试净距为 0.1220、0.1227 米，零速命令延迟为 0.305、0.330 秒，实际持续停稳延迟为 0.530、0.540 秒。相较 B 的失败观察到改善，但样本很少，且余量仍小，不能称为统计显著或鲁棒性已经充分验证。

这不是“每次规划都只需几毫秒”。复杂组合搜索仍有约 240 毫秒长尾；`max_search_time_ms=90` 约束的是其中的搜索阶段，不是整个组合任务。部分长搜索持有地图锁，控制端曾因内部地图年龄超过 0.50 秒停车，随后恢复。控制有独立防护，但这一争用仍应解决，不能提高超时门限掩盖。

103036 超时帧的增强节点诊断记录为计算 68.5 毫秒、节点读取到的源年龄 0.115 秒，而独立接收器记录为 0.465 秒。因此不能直接归咎于“GP 计算用了 465 毫秒”。节点时钟更新、发布后的排队/调度和消费者处理需进一步分别观测；当前证据不足以唯一定位。相同版本复测通过不代表此问题已修复。

## 7. 剩余准入工作

1. 将规划地图与控制地图的更新生命周期解耦，解决长组合搜索阻塞新地图的争用；保持逐状态、全车身和预算检查，不用放松安全条件换速度。
2. 分别记录时钟/生产/传输/消费时间和队列状态，定位偶发风险图超时；在相同构建下重复通过，而不是仅筛选通过记录。
3. 下坡动态最小净距只有约 12 厘米，余量仍小；还需要横穿速度、方向、不同遭遇时刻、加减速和遮挡变化检查。当前常平移运动模型不是任意动态行为保证。
4. 当前版本尚未完成正面穿过高横梁、低横梁必须拒行的成对物理资格；这部分目前是几何/CPU-GPU/边界回归，不应冒充整场景实测。
5. 累计点云的坡面残影计数仍有平地 ROI 假设，本次不将其当作坡面动态去影定量结论。动态导航通过也不证明 FAST-LIO 全局地图已完全无残影。
6. 外部算法对比、大样本导航成功率、CPU 兜底的运动时效和陡坡极限需要独立审阅协议。本次只进行获准的定向资格，不启动论文批量实验。
