# 概率地形导航：定向边界资格检查

2026-10-28 的车头误高风险、地面融合和台阶事件语义修订及未通过记录，见 [风险源层排查](RISK_LAYER_DIAGNOSIS_20261028.md)。本文保留此前版本资格设置，不能将其结果混入新的契约 6。

本轮针对导航功能边界排查和修正。它不是已审定的大规模对比实验，也不能据此声明通用高成功率。原始失败记录保留；每个物理运行在 `log/modular_smoke_20261027_*` 中冻结输入 JSON、源码 ZIP、关键文件及运行程序哈希。

## 要回答的问题

普通导航的“到达且不碰撞”仍是必要条件。概率导航还必须核查：给定后验和模型假设时，实际执行命令是否满足当前姿态、局部路径和可停车轨迹的风险预算；补全遇到断层、外推和模型失配时是否误放行；模型拒绝的物理可行场景有多少。风险数字低不能代替这些检查。

当前 `shared_gp` 是有限特征共享高斯地形后验和工程模型误差场，尚不是经过实地标定的失效概率。预算为姿态 0.05、局部路径 0.10、制动 0.05，路径事件通过保守联合预算处理，不能将各位置的安全概率直接相乘。

## 场景与通过条件

| 场景 | 实际测试对象 | 不能混淆的情况 |
|---|---|---|
| 24 m 长走廊 | 单一目标在出口之后且超出初始 20.8 m 局部图；循环更新地图并连续前进 | 带墙缝几何特征的走廊不代表无特征走廊定位已经解决 |
| 走廊中部、墙外目标 | 两端各距起点 12 m，目标隔墙但很近；必须暂时远离目标，寻找出口再绕回 | 不能预设中途航点，不能把测试器知道的出口告诉规划器 |
| 密集障碍 | 25 个有物理碰撞的圆柱，固定随机种子；没有刻意保留中心直通带 | 单个柱子成功不等于密集场景成功 |
| 交替窄门 | 三个交错门洞，考察转弯半径、车身扫掠、转向变化和重新规划 | 几何上有空隙不等于汽车运动学可达 |
| 6/16 cm 台阶碎石 | 8 条横跨车道的台阶及 24 个小块，车轮必须实际接触通过 | 这是刚性块体地形，不模拟松散碎石的颗粒流动、沉陷和轮胎切向摩擦变化；16 cm 不预设可通过 |
| 三动态物体 | 两个反向横穿物体和一个慢速前行物体，均为连续运动的物理碰撞体 | 场景里存在三个物体不等于确实发生了三次避让；需另查相遇与轨迹 |
| 坡度/曲率/断层/缺测组合 | 32 个解析地形与缺测输入、每个 3 个航向，共 96 个姿态查询 | 96 个查询不是 96 个独立物理世界，也不是概率校准实验 |

物理检查使用实际真值轨迹、完整车身平面外廓（前 0.58 m、后 0.48 m、半宽 0.40 m）与测试障碍物的分离距离，要求至少 0.10 m；不缩小车体来提高通过率。台阶另检查真实底盘箱体下表面到台阶面的高度，车轮接地不算车体碰撞。所有距离都是离散采样的参考检查，不是全世界连续网格碰撞证明。

还检查到达后停车、定位与独立真值的固定初始对齐误差、地图消息年龄、命令间隔和记录器是否溢出。当前到达条件只检验位置与停车，不声称已检验终端航向精确收敛。

## 本轮修正及反例

1. **已知地面断层旁的平滑补全。** 原检查中，20 cm 台阶旁缺测半径约 0.6 m 时，模型给出了约 0.010 的条件风险，独立密集几何参考的残差跨度约 0.202 m，超过 0.18 m 限制。增加缺测域断层保护，保留原始实测地面，不伪造高度或降低风险预算。
2. **墙体不能充当地面断层证据。** 首版保护把占用柱中的高低散乱回波当成地面跳变，误删走廊地板的补全域。现排除占用柱作为地面断层见证，柱本身仍由完整车身碰撞和当前点云拦截。相关平坦走廊与真实台阶反例均有 CPU/CUDA 回归。
3. **初始支撑的定位时序。** 显式仿真支撑假设改为首次规划目标确认后才开始稳定性检查；固定后不随车辆或后续目标扩张。规划器通过 `/terrain_nav/received_goal` 确认收到目标，可靠保留首条确认以避免发现时序丢失；地形节点拒绝超过 2 s 的旧确认，避免重启时用旧任务重新初始化。固定前已有非零运动命令则禁止建立该假设。实车仍默认未知。
4. **实验记录器。** 修正 NumPy 布尔值导致结果 JSON 保存失败的问题；不把“日志显示到达但原始记录保存失败”计作通过。原始运动占用栅格可以归档重放。启动阶段子进程退出时快速失败。

解析定向检查目前为 **0 个危险误放行、23 个参考几何可行但被拒绝、37 个未知姿态**，分母 96。后两项说明仍有明显保守性，不能只报告第一项。参考只检验密集足迹平面斜率、横滚和残差跨度，并不证明轮胎实际能够爬过某个台阶。

## 复现单个物理场景

先构建已修改模块并加载环境：

```bash
source /opt/ros/humble/setup.bash
colcon build --packages-select terrain_nav fsgp_bgk_se2 --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
```

下面每次只运行一个场景；将 JSON 文件名改为同目录中的其他案例即可。检查器启动并清理它拥有的四个模块进程，保留 GUI、RViz 和日志，不使用场景真值来控制车辆。

```bash
python3 scripts/sim/checks/pipeline_smoke.py \
  --gui --rviz-view risk \
  --prediction-backend feature_sgp --gp-complete-supported \
  --probability-model shared_gp \
  --startup-support stable_stance --directional-startup-support \
  --gp-support-distance 1.25 --gp-extrapolation-distance .75 \
  --reverse-recovery \
  --obstacle-memory-topic /Laser_map --obstacle-memory-role advisory \
  --dynamic-filter-backend freedom \
  --trial-scenario boundary \
  --boundary-spec scripts/sim/experiments/boundary_cases/long_corridor.json \
  --capture-motion-grid --trial-timeout 110
```

本命令中的扩展补全域与固定起始假设是显式仿真资格设置，不应直接当成已验证的实车设置。测试器真实通过与否见运行目录 `navigation_data.json` 和 `result.json`，不能只看终端中的某条规划成功日志。

## 效率数据的口径

- `planning.log` 中每条 `terrain_nav planner: result=... elapsed=...ms` 都纳入统计，成功搜索与失败搜索分开列出；0 ms 的支撑拒绝不能当成快速规划成功。
- 风险图年龄为消息时间戳到接收时仿真时间的差；命令间隔来自完整接收序列。它们不是 GPU 核函数时间，也不单独等于从目标到车轮响应的总延迟。
- `control timing` 是节流诊断，不能据此声称全部控制周期无超时。
- 新旧方法版本的运行分别保留，不能将修正前后混为同一个成功率。大量独立地形、不同种子、光滑/突变坡、定位退化和实测概率校准仍需后续方案审阅。
