# 墙边和车后异常地形风险：源帧排查与修正

本记录针对2026-11-02截图中的异常红带。它不是论文批量实验、成功率统计或概率校准报告。旧失败保留；没有提交或推送GitHub。

## 两项已定位的问题

1. **已测地面因当前遮挡而失去似然。** GP训练排除了柱子邻域中当前扫描看不到的格子，却又用未条件化的局部残差覆盖这些原本有实测高程的格子。连续33格足迹中若干原始标准差约1 cm的地面，模型标准差升到约5.3 cm。平地均值仅有毫米级起伏，联合地形上界却达到0.85。这是源选择错误导致的过度保守，并非实测85%的失败率。
2. **柱面高度混入地面。** 原始高程融合中会保留柱面低处回波；当前柱子被遮挡后，该格仍可能显示为低方差“地面”。冻结输入中发现了约高于附近地面23 cm的这种样本。它被整车地形足迹反复计算为台阶，又与独立柱体碰撞叠加，产生柱后红块。只修改膨胀半径不能解决。

## 修正后的数据关系

地面是条件随机场 `h(x,y) | D_ground`，输出均值与协方差；竖直占据是独立的原始回波几何。规划仍同时要求：完整车身不与占据体相交、地形状态上界合格、整段路径与制动预算合格。预测地面不能覆盖任何一项碰撞检查。

- 原始可靠地面在当前被车身或墙遮挡时仍参与原有似然，保留原始噪声；预测、起始假设不充当训练数据。坑洞、待确认变化和独立负向证据仍立即撤销支撑。
- 当前正向柱体与仍有效的历史竖直几何只用于**排除柱面/顶部的地面标签**。历史地图仍是导航引导信息，不被提升为当前硬占据或实测地面。
- 柱下的潜在地面可在相同距离、观测域、方差与负向证据限制下预测。它明确标记为GP预测，不能标记为实测。未获准时仍是未知。
- 原始柱体、细分占据子格和完整车身检查保留。不能因为预测了柱下地面就让车辆穿过柱子。
- 负回波也可能被保守的占据检测器标记。它不是正向柱体；必须保留原始地面的坑洞对照。回归曾捕获过误屏蔽该见证的候选修改，已改为用回波上沿相对原始地面区分正向柱，原单点坑洞撤销与多帧清除检查仍通过。

序列化增加 `gp_model_ground_observed`、`gp_model_positive_columns` 与两个显式模型开关。原始高程和原始观测标签保留供审计；训练来源另行记录。历史模型默认关闭新开关，可按源帧元数据重放，不用当前实现冒充旧模型。

原生规划器6个测试程序、208项回归通过；之前的相关Python安全回归143项通过，新增显示回归10项通过，包括CPU/CUDA地面源选择、柱体不成为训练地面、柱高变化不改变潜在地面、坑洞、待确认变化、起始源、混合协方差与消息身份检查，以及本次新增的精确邻域搜索、受限死角退让与断流后重新校验。安装目录28个运行文件与源码一致。Python两组有交集，不能相加充当独立测试数。

原有保护车身前伸/后伸/半宽为0.68/0.58/0.50 m，含单次0.10 m余量；状态、路径、制动上界预算仍为0.05/0.10/0.05。0.18 m仍只是未完成实物标定的几何代理阈值。

之前版本的密集、窄门及台阶拒绝检查均有未通过记录。柱体/地面分离后仍未通过窄门及密集场景；5厘米几何版也未通过。后续实时计算修正版的窄门已通过，密集场景仍失败。不同修改版本不合并计算成功率。

## 5厘米几何和实时计算修正

窄门冻结帧中发现：10厘米障碍子格有一格因栅格外扩与完整保护车身产生毫米级交叠。原始回波与其2厘米定位垫边没有交叠。仅提高地形占据和实时避障几何到5厘米，保持原始粗占据格、回波垫边和全部物理尺寸不变；缺少子格见证时仍保守使用整个父格。

[同源几何重建](../log/fine5cm_source_qualification_20261102/geometry_qualification.json)重建旧子格零差异。地形与实时几何同时使用5厘米后，原停止位及前方8个查询通过原生单状态检查。它们只是同帧9个查询，不能替代联合路径、制动或物理导航验证。

细化后旧实时避障程序在每个空格上重复遍历邻域，造成点云过期停车。修正为从有限观测源散播精确圆盘邻域，并保持最近距离、同距时的原行列次序；同一父格的地面/净空最近邻查询只做一次。回波碰撞仍在5厘米格中计算。

[精确性与耗时记录](../log/live_column_latency_20261102/qualification.json)：48组输入的1,424,394个输出值无差异；密集场景同源帧查询结果相同，回调由原日志间隔约379毫秒降到约44毫秒。这是单帧记录，不是耗时分位数或GPU加速结果。

## 密集死角中未倒车的修正

该失败帧当前保护车身和地形均合格，向后直线约3.6米的逐段检查也合格，但原恢复模块依赖全局粗栅格生成“倒车+前进出口”的配对方案。粗栅格报起点阻挡，配对方案失败，恢复计数始终为0。

保留原配对恢复，增加独立的**有限倒车、停稳、重新找路**阶段：

- 仅在普通规划失败、车辆已停止且附近有障碍时考虑；默认先试直线，受车辆曲率限制的圆弧作为候选。
- 单段最多2.5米且不超过既有倒车距离限制，至少有0.6米合格退让；逐段检查当前完整保护车身、实测/合格预测地面及同一整段风险账户。
- 它不声称已知未来前进出口，不声称完成目标。每个实际倒车控制周期仍经过原制动包络与动态障碍检查。
- 确认停稳后清除退让路径，从新观测重新前进搜索，保留最终目标。倒车位移不会重置恢复计数；只有原有合格前进进度才能释放连续重试限制。每目标总次数限制保留。
- 失败分支只增加有限、会过期的路线偏好，不改变占据、支撑、概率值或安全预算。RViz面板增加恢复阶段和连续/累计次数。

[原生恢复派发重放](../log/live_column_latency_20261102/deadend_dispatch.json)在这次实际失败源帧上生成并派发2.5米退让路径；这仍只是离线验证，不表示物理退出成功。

首个[受限退让物理版本](../log/deadend_retreat_capabilities_20261102/qualification.json)仍失败。在线确实生成了2.4米配对恢复和2.5米独立退让，但短暂地图过期时旧程序清空了恢复路径；数据恢复后重新前进，两次恢复次数却已消耗。该版本记录了7.75米行程、约9.63米最终误差；物理包络检查通过，任务未通过，不能把“出现了负速度”当作完整恢复成功。

进一步修正保留**仅限5秒的恢复几何意图**：过期仍立即停车，`have_path=false`使控制器不能执行保存的路径。时效稳定后，工作线程必须对剩余腿重新执行当前完整车身、支撑、联合风险检查，再恢复执行，且不新扣一次恢复次数。帧/契约代际变化、失去支撑、出现新占据或保存过久都不能续用。保存几何不等于缓存安全证明。有限路线偏好和恢复进度标识仅在成功重新校验后迁移到新的时效代际，原计数和时间衰减不变。

该修正对应[原生回归](../log/deadend_resume_native_20261102.log)，并在[独立密集复测](../log/deadend_resume_capabilities_20261102/)中验证。最终到达与安全字段仍以物理原始记录为准。
